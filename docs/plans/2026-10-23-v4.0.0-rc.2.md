# OverGate v4.0.0-rc.2 — план

**Цель:** выпустить второй кандидат `v4.0.0-rc.2` из исправлений пайплайна, которые после rc.1
прошли эксплуатацию в двух установках-источниках, в обезличенном виде, пригодном для любого проекта.

**Решение оператора 2026-10-23:** следующий релиз — `v4.0.0-rc.2`, `prerelease=true`,
`make_latest=false`. Перевод в stable 4.0 — отдельное решение позже. Stable `v3.9.0` остаётся Latest.

**Режим:** CRITICAL — pipeline governance: меняются managed Beads-обёртка, managed settings
(allow-правила) и тесты-стражи, которые получат все установленные проекты. Budget — 6 независимых
verifier launches: Plan Review 1, QA 2, Code Review 3, affected QA 4, scoped re-review 5, резерв 6.

**Стек:** этот PR стоит на Draft/ready PR #8 (`codex/beads-environment-guide`, docs Beads, FINAL
ACCEPTANCE от 2026-10-04, ждёт merge оператора). После merge #8 база PR переключается на `main`.

## 3. Шаги реализации

1. **Страж bash 3.2 (D1).** Перенести тест; опоры `ANCHORS` — `.claude/hooks/pre-bash.sh` и `scripts/verify-reference.sh`; области `.claude`, `.codex`, `scripts`, включая `command` хуков в `.claude/settings.json` и `.codex/hooks.json`. Сначала RED: временная мутация `«$label»` в dispatcher → тест FAIL; GREEN на текущем дереве. Ссылки на задачи/PR U2 в тексте теста заменить на нейтральное описание класса.
2. **Embedded/server и allowlist (D3, D4).** Перенести логику U2 Lab в managed `bd-wt.sh`/`bd-env.sh`; Python — через launcher проекта (R6). Обезличить: без «адаптации Lab», U2 ADR-номеров и `ulab-*`; ссылаться на `.claude/rules/beads.md` и `PIPELINE_ADR §3.7`. Сообщения отказа — с `bash scripts/...`. Allow-правила — в managed `.claude/settings.json`.
3. **Тесты обёртки (D5).** Сохранить все существующие кейсы `bd-wt.test.sh`, которые не противоречат allowlist; противоречащие — переписать явно с обоснованием в PR. Добавить кейсы из U2 Lab для обёртки и `bd-env` без applier. Идентификаторы в фикстурах — нейтральные (`proj-1`).
4. **Предписания `bash` (D2).** Перевести только инструкции к запуску; упоминания путей оставить. Проверить, что гейт коммита в rc.2 по-прежнему блокирует прямой запуск без аргументов (это задокументированное поведение, не дефект для исправления).
5. **Distribution/installer.** Обновить manifest и closure. Добавить фикстуру upgrade **rc.1 → rc.2**: проект, установленный из тега `v4.0.0-rc.1`, обновляется без конфликтов; проект с изменённым managed `bd-wt.sh` (форма U2 Lab) получает адресный conflict, а не тихую перезапись; rollback возвращает байты.
6. **Версия и документы.** `4.0.0-rc.2` во всех version-полях; тексты «в rc.1 допускается…» — нейтрально к версии там, где ограничение действует и в rc.2. CHANGELOG, README, provenance (источники U2 `4a7354ea7` и U2 Lab `5586b43`, file-level: путь, blob, адаптация).
7. **Публикация после merge.** Только после merge оператором: тег `v4.0.0-rc.2` на exact merge SHA, GitHub release `prerelease=true`, `make_latest=false`; проверка, что Latest остался `v3.9.0`.

**Edge/error:** `.beads/metadata.json` без `dolt_mode` — в источнике fail-closed с адресным
сообщением; сохранить. Если окажется, что поддерживаемые bd (≥ 1.0) могут не писать `dolt_mode`,
это регрессия к rc.1 для server-установок: Developer фиксирует факт по bd 1.2.x, и такой случай
идёт в CHANGELOG как `DECLARED_LIMIT` с шагом восстановления. `--` перед подкомандой; значение
аргумента, равное запрещённому флагу (`--title -C`) — осознанный отказ.

**Инварианты:** dispatcher-семантика, recovery DECLARED_LIMIT и guards rc.1 не меняются; applier не
появляется в inventory; `.beads/dolt/**` и snapshot руками не правятся; merge — только оператор.

**Named risks:**
- R1 — allowlist ломает рабочие сценарии существующих проектов (основной checkout теперь тоже фильтруется). Метод: перечень изменённых кейсов `bd-wt.test.sh` с обоснованием; CHANGELOG «Changed».
- R2 — allow-правило без подтверждения открывает обход базы. Метод: AC-03/04 на обеих формах вызова (`scripts/…` и `bash scripts/…`).
- R3 — upgrade U2 Lab-подобного проекта тихо перезаписывает override или падает без адреса. Метод: AC-08.
- R4 — страж bash 3.2 зелёный из-за пустого перечисления. Метод: опоры и unit-кейсы перечисления (AC-01).
- R5 — утечка специфики U2 в generic payload. Метод: AC-09.
- R6 — переносимость на Windows: источник читает `metadata.json` через `python3 -I` напрямую, а
  OverGate запускает Python через `.claude/tools/run-python.sh`. Метод: обёртка использует
  launcher проекта либо доказанно переносимый парсер; кейс в `windows-native` CI.

## 5. Rollback

До релиза — revert PR. После публикации rc.2 — пометить release как отозванный в описании и
выпустить rc.3; тег не удаляется и не переносится. Установленные проекты откатываются штатным
rollback installer по backup.
