# OverGate v4.0.0-rc.2 — план

**Цель:** выпустить второй кандидат `v4.0.0-rc.2` из исправлений пайплайна, которые после rc.1
прошли эксплуатацию в двух установках-источниках, в обезличенном виде, пригодном для любого проекта.

**Решение оператора 2026-10-23:** следующий релиз — `v4.0.0-rc.2`, `prerelease=true`,
`make_latest=false`. Перевод в stable 4.0 — отдельное решение позже. Stable `v3.9.0` остаётся Latest.

**Режим:** CRITICAL — pipeline governance: меняются managed Beads-обёртка и тесты-стражи, которые
получат все установленные проекты, и CI. Budget — 6 независимых verifier launches: Plan Review 1
(использован), QA 2, Code Review 3, affected QA 4, scoped re-review 5, резерв 6. Повторная проверка
плана — в той же сессии Reviewer.

**PR и база:** Draft PR #10, ветка `chore/u2-pipeline-sync`, база `main` `511023e` (merge PR #8,
docs Beads). Первый Draft #9 GitHub закрыл автоматически при удалении базовой ветки #8.

**v0.2:** блокеры Plan Review 1 — B1 allow-правила исключены (D4), B2 Windows-проверка обёртки в CI
(R6, шаг 6), B3 база обновлена; приняты advisory 1–9 как уточнения без расширения поставки.

## 3. Шаги реализации

1. **Страж bash 3.2 (D1).** Перенести тест; `ANCHORS` — `.claude/hooks/pre-bash.sh` и `scripts/verify-reference.sh`; области `.claude`, `.codex`, `scripts` плюс `command` хуков `.claude/settings.json` и `.codex/hooks.json`. RED: временная мутация `«$label»` в dispatcher → FAIL; GREEN на HEAD. Ссылки на задачи/PR U2 в тексте теста — нейтральным описанием класса.
2. **Embedded/server и allowlist (D3, D4).** Перенести логику U2 Lab в managed `bd-wt.sh`/`bd-env.sh`. Python для чтения `metadata.json` — только через `.claude/tools/run-python.sh` (R6); отказ launcher — адресное сообщение «нужен Python», а не диагноз «не JSON». Обезличить: без «адаптации Lab», U2 ADR-номеров, `ulab-*`; ссылаться на `.claude/rules/beads.md` и `PIPELINE_ADR §3.7`. Сообщения отказа — с `bash scripts/...`.
3. **Тесты обёртки (D5).** Существующие кейсы `bd-wt.test.sh` сохраняются по смыслу; worktree-фикстуры получают `metadata.json` с `dolt_mode: server`, ID — `proj-1`. Единственное изменение поведения — `--global` из разрешённого флага становится отказом: кейс переписывается явно, в CHANGELOG «Changed». Добавить кейсы U2 Lab для обёртки и `bd-env` без applier, включая проверку, что resolver вызывает launcher проекта.
4. **Предписания `bash` (D2).** Перевести только инструкции к запуску; упоминания путей оставить. Сверить вызывающих обёртку в payload (finalize-pr `bash scripts/bd-wt.sh show -- <id>`, docs ready/show/create/update --claim/close) — все в allowlist.
5. **Distribution/installer.** Обновить manifest и closure. Фикстура upgrade **rc.1 → rc.2**: проект из точной установки `v4.0.0-rc.1` обновляется без конфликтов; проект с изменёнными managed `bd-wt.sh` и `bd-env.sh` (форма U2 Lab) получает адресный conflict по каждому, а не тихую перезапись; rollback побайтный. CHANGELOG/INSTALL: preserve-файлы (`.claude/rules/beads.md`, `AGENTS.md`) при upgrade не обновляются — правки D2/D4 переносятся проектом вручную по указанному diff.
6. **Windows CI (R6).** В `windows-native` — шаг Git Bash с тестом обёртки (embedded и server на заглушке bd, через launcher проекта).
7. **Версия и документы.** `4.0.0-rc.2` во всех version-полях; тексты «в rc.1 допускается…» — нейтрально к версии, где ограничение действует и в rc.2. CHANGELOG, README, provenance (U2 `4a7354ea7`, U2 Lab `5586b43`; путь, blob, адаптация).
8. **Публикация после merge.** Только после merge оператором: тег `v4.0.0-rc.2` на exact merge SHA, GitHub release `prerelease=true`, `make_latest=false`; Latest остаётся `v3.9.0`.

**Edge/error:** отсутствующий `dolt_mode` — fail-closed, без fallback: все известные формы (`server` в
U2, `embedded` в U2 Lab и OverGate) его проставляют. Сообщение называет шаг восстановления штатной
командой bd, без ручной правки `.beads`. `--` перед подкомандой; значение аргумента, равное
запрещённому флагу (`--title -C`), — осознанный отказ. Конкуренция за lock embedded Dolt при
одновременных процессах в основном checkout и worktree — описать в `beads.md` как ограничение.

**Инварианты:** dispatcher-семантика, recovery DECLARED_LIMIT и guards rc.1 не меняются; `allow`
managed settings не меняется; applier не появляется в inventory; `.beads/dolt/**` и snapshot руками
не правятся; merge — только оператор.

**Named risks:**
- R1 — allowlist ломает сценарии существующих проектов (основной checkout теперь тоже фильтруется). Метод: шаг 3 (явный перечень изменённых кейсов, `--global`), шаг 4 (вызывающие в payload), CHANGELOG «Changed».
- R2 — обёртка как маршрут обхода основной базы через флаги/переменные окружения. Метод: AC-03/04 на обеих формах вызова (`scripts/…` и `bash scripts/…`). Allowlist — защитный слой обёртки, не граница безопасности: прямой `bd` остаётся доступен в рамках `Bash(*)`.
- R3 — upgrade U2 Lab-подобного проекта тихо перезаписывает override или падает без адреса. Метод: AC-08.
- R4 — страж bash 3.2 зелёный из-за пустого перечисления. Метод: опоры и unit-кейсы (AC-01).
- R5 — утечка специфики U2 в generic payload. Метод: AC-09.
- R6 — переносимость на Windows: источник вызывает `python3 -I` напрямую, на Windows это может быть заглушка Store. Метод: launcher проекта (шаг 2), unit-проверка вызова, Windows-шаг CI (шаг 6, AC-10).

## 5. Rollback

До релиза — revert PR. После публикации rc.2 — пометить release как отозванный в описании и
выпустить rc.3; тег не удаляется и не переносится. Установленные проекты откатываются штатным
rollback installer по backup.
