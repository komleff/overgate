# og-4py — Beads синхронизирует и публикует задачи с обычным входом пользователя на GitHub

## Источник и решение оператора

Beads `og-4py` (P0). Воспроизведено 2026-11-09 на Mac оператора: `bash scripts/bd-sync-export.sh`
падает с «could not read Username for https://github.com: terminal prompts disabled», обычный
`git push` из того же checkout проходит.

Оператор 2026-11-10 (дословно), о требовании ручной настройки входа (`git config --local
credential…helper`) для синхронизации задач: «Это ручное говно, а не автоматический пайплайн! … Я
твой процесс предлагаю своим коллегам как удобную автоматизацию».

WHAT: пользователь, у которого обычный `git push` в проект работает, синхронизирует и публикует
задачи Beads (legacy и managed route) без дополнительной настройки Git. Ручной шаг — дефект.

Вынесено из rc.5.2 PR #19 по Plan Review v0.2 (BLOCKER 2, advisory «уменьшение scope»):
[PLAN REVIEW](https://github.com/komleff/overgate/pull/19#issuecomment-6748693950). Замечания того
review по og-4py учтены ниже.

## Target → as-built → gap

| Surface | As-built (`b04b21c`) | Target |
|---|---|---|
| Изоляция git config в Beads-маршрутах | Сбрасывают caller `GIT_*` и ставят `GIT_CONFIG_GLOBAL=/dev/null` (`NUL` на Windows) + `GIT_CONFIG_NOSYSTEM=1`: `scripts/lib/bd-env.sh` (`bd_env_sanitize_git` → `bd-sync-common.sh`, `bd-wt.sh`, `bd-bootstrap.sh`), собственные преамбулы `scripts/bd-read.sh:19-24`, `scripts/bd-apply-intents.sh:10-15`, `scripts/lib/bd-git-environment.mjs` (`cleanGitEnvironment`), `scripts/lib/bd-managed-cli.mjs:40`, `scripts/bd-activate.py:152`, `scripts/bd-upgrade-preserve.py:72`, `scripts/install-overgate.py:36` | Изоляция от caller env, alias, `url.*.insteadOf`, `core.hooksPath`, `include` и прочих ключей сохраняется. Маршруты, которые ходят в сеть или создают коммиты снимка, получают из global/system только allowlist: `credential.*` (включая `credential.<url>.*`) и `user.name`/`user.email` |
| Preflight managed publisher | `assertPublisherIdentityAndAuth` (`scripts/bd-publisher-setup.mjs:62-77`) и `publisher_identity_auth` (`scripts/bd-activate.py:131-147`) требуют **repo-local** `credential.helper` (HTTPS) и repo-local identity; тест `scripts/tests/bd-publisher-setup.test.mjs:93-94` закрепляет «isolated writer cannot rely on global/system credential helper» | Preflight принимает helper и identity из effective config изолированного git (local + allowlist из global/system). При отсутствии helper — прежний fail-closed, без интерактивного запроса |
| Контракт оператора | `.agents/HOW_TO_USE.md:193-196`: «Для HTTPS нужен доверенный repo-local credential.helper … Унаследованные global/system Git config … не используются» | Контракт: publisher использует обычный вход пользователя (helper из global/system, например `gh auth setup-git`, Git Credential Manager, osxkeychain); прочие global/system ключи и caller `GIT_CONFIG_*` по-прежнему не используются |

## Решение (HOW, PM)

Allowlist-перенос: перед первым git-вызовом маршрута, **после** сброса caller `GIT_*`, прочитать
`git config --system --includes --get-regexp` и `git config --global --includes --get-regexp` для
ключей allowlist и записать их (порядок system → global, multi-value и пустой `helper =` как есть)
в приватный временный файл маршрута (вне repo, права только владельца, удаляется на выходе),
который подключается как `GIT_CONFIG_GLOBAL`; `GIT_CONFIG_NOSYSTEM=1` остаётся. Так перенесённые
ключи имеют scope global, и repo-local значения сильнее, как в обычном git. `GIT_CONFIG_COUNT` не
используется: это command scope, он перекрыл бы local. Единый allowlist и одна семантика для
shell, mjs и python (тест паритета). Файл создаётся один раз на процесс маршрута.

Позиция доверия: helper (в том числе `!cmd`) — тот же, что исполняет обычный `git push`
пользователя; источник — `HOME`/`XDG_CONFIG_HOME` и system config того же пользователя. Caller
`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`/`GIT_CONFIG_*` для поиска не используются (существующий
тест `bd-publisher-setup.test.mjs:100-104` сохраняется).

Отклонённые варианты:

- *Ручной `git config --local credential.helper`* — отклонён оператором.
- *Автоматически записывать helper/identity в repo-local config при setup/activation* — снимок
  устаревает при смене входа (`gh auth`), меняет Git config пользователя без запроса, не
  покрывает legacy route до activation.
- *Снять изоляцию global/system целиком* — возвращает `url.*.insteadOf`/alias/hooks, от которых
  изоляция защищает идентичность remote.
- *Переносить `http.*` (proxy, `sslCAInfo`)* — вне scope этого hotfix (residual ниже).

## Scope / non-goals

IN: перечисленные файлы изоляции и preflight; их тесты (`scripts/tests/bd-*.test.*`,
`scripts/test-bd-sync.sh`, `scripts/tests/bd-publisher-setup.test.mjs`); `.agents/HOW_TO_USE.md`
(абзац контракта); `.agents/INSTALL.md`, если содержит тот же контракт; ADR-запись (смена контракта
managed Beads, с «Отклонёнными вариантами»); CHANGELOG; migration notes.

OUT: `http.*`/proxy (residual: у коллег за корпоративным proxy остаётся настройка — отдельная
задача Beads); SSH route (без изменений); Windows gate (PR #19); перерегистрация publisher у
установленных проектов.

Residual / migration: копия `bd-git-environment.mjs` в controlDir pre-push hook установленных
проектов остаётся старой до перерегистрации — безвредно (guard не делает push); `SOURCE_FILES`
pins сверяются только при setup. Установленные rc.5+ получают поведение через upgrade.

## Шаги

1. **Inventory (RED).** Тест-таблица маршрутов: какие делают fetch/push/commit-tree
   (`bd-sync-export`, `bd-sync-restore`, `bd-read`, `bd-apply-intents`, managed publisher,
   `bd-activate`, `bd-wt`, `bd-bootstrap`, installer/upgrade). Для каждого — решение: allowlist
   или «сеть не нужна, изоляция полная».
2. **RED.** Fixture HOME с global config (`credential.helper` из `gh auth setup-git`-формы с пустым
   сбросом, `credential.https://github.com.helper`, `user.name/email`, `url.*.insteadOf`,
   `alias.*`, `core.hooksPath`, `include.path` на файл с helper) + system config: после sanitize
   helper и identity видны, остальное нет; local helper побеждает global; caller
   `GIT_CONFIG_GLOBAL` игнорируется. Shell, mjs, python.
3. **Fix** allowlist-переноса в общих helpers; собственные преамбулы маршрутов переводятся на них.
   На Windows путь временного файла для нативного `git.exe` — в Windows-формате (`cygpath -m`, как
   `bd_env_native_path`); ошибка преобразования → fail-closed.
4. **Preflight** publisher/activation: effective helper/identity; тест 93-94 меняется на новый
   контракт (смена контракта — ADR, до кода шага 4).
5. **Живая проверка** на Mac оператора: `bash scripts/bd-sync-export.sh` без repo-local helper.
6. HOW_TO_USE/INSTALL, ADR, CHANGELOG, Memory Bank.
