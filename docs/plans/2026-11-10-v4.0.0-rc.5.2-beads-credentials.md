# og-4py — Beads синхронизирует и публикует задачи с обычным входом пользователя на GitHub

## Источник и решение оператора

Beads `og-4py` (P0). Воспроизведено 2026-11-09 на Mac оператора: `bash scripts/bd-sync-export.sh`
падает с «could not read Username for https://github.com: terminal prompts disabled», обычный
`git push` из того же checkout проходит.

Оператор 2026-11-10 (дословно), о требовании ручной настройки входа (`git config --local
credential…helper`) для синхронизации задач: «Это ручное говно, а не автоматический пайплайн! … Я
твой процесс предлагаю своим коллегам как удобную автоматизацию».

WHAT: пользователь, у которого обычный `git push` в проект работает, синхронизирует и публикует
задачи Beads (legacy и managed route) и ставит/обновляет OverGate без дополнительной настройки Git.
Ручной шаг — дефект.

Вынесено из rc.5.2 PR #19 по Plan Review v0.2 (BLOCKER 2):
[PLAN REVIEW #19](https://github.com/komleff/overgate/pull/19#issuecomment-6748693950). Plan Review
v0.1 этого PR (CHANGES_REQUIRED, 6 BLOCKER, пробы на Apple Git 2.50.1) учтён в v0.2.

## Решение (HOW, PM)

**Allowlist:** `credential.*` (включая `credential.<url>.*`), `user.name`, `user.email`.

**Чтение.** Один раз на процесс маршрута, лениво (при первом сетевом вызове), из корня целевого
репозитория, после сброса caller `GIT_*`:
`git config --show-scope --includes -z --get-regexp '<allowlist regexp>'` без флага scope.
Берутся записи со scope `system`, `global`, `unknown` в порядке вывода; `local`, `worktree`,
`command` отбрасываются (local git прочитает сам). Чтение идёт **без** `GIT_CONFIG_NOSYSTEM` и
без любых caller `GIT_CONFIG_*` (иначе теряется scope `unknown`/system: проба Reviewer на Apple
Git 2.50.1). В production унаследованный `GIT_CONFIG_NOSYSTEM` не учитывается вообще: его нельзя
отличить от NOSYSTEM родительского маршрута (`bd-apply-intents.sh` → node, `bd-activate.py` →
setup/apply/read, `bd-bootstrap.sh` → `bd-sync-restore.sh`, `bd-wt.sh` → `bd-read.sh`), и иначе
вложенный маршрут терял бы osxkeychain/GCM. Негативные тесты используют reader-seam с пустым
результатом. Код возврата не из {0, 1} → fail-closed. Требуется Git с
`--show-scope` (≥ 2.26); иначе fail-closed с диагностикой.

**Перенос.** Записи пишутся в приватный временный файл (`mkdtemp` 0700, файл 0600, вне repo) через
`git config --file <tmp> --add <key> <value>` из `-z`-вывода (одинаково в shell/mjs/python;
корректно для subsection с пробелом и значений с `"`, `;`, `#`). Файл подключается как
`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM=1` остаётся. Семантика совпадает с обычным git:
однозначные ключи (`user.name`/`user.email`) — побеждает последнее значение, т.е. local;
список `credential.helper` — порядок system → global(→unknown по выводу) → local и сброс пустым
`helper =` как у обычного git. `GIT_CONFIG_COUNT` не используется (command scope). На Windows путь
файла — native-форма (`cygpath -m`, как `bd_env_native_path`); ошибка → fail-closed.

**API и жизненный цикл.**
- `cleanGitEnvironment` (mjs), `bd_env_sanitize_git` (shell), python-аналоги остаются **чистой
  изоляцией** без файлов. Новые функции `networkGitEnvironment(root)` / `bd_env_network_git <root>`
  / python-аналог — только для `ls-remote`/`fetch`/`push`/`commit-tree` снимка.
- Файл создаётся лениво; удаление: shell — цепочка к существующей ловушке EXIT/INT/TERM (не
  замена; `bd-read.sh:79`, `bd-sync-export.sh:36`, `bd-sync-restore.sh:25`). Файл, созданный для
  сетевого вызова в процессе, который затем делает `exec` (`bd-apply-intents.sh:35` ls-remote →
  `:49` exec; `bd-wt.sh:167,179` в `$(remote_mode)` → exec), удаляется **до** `exec` и в
  exec-окружение не передаётся: дочерний процесс получает чистую изоляцию и при сетевом вызове
  создаёт свой файл. Для subshell/command substitution время жизни ограничено subshell с
  собственной ловушкой. Node — `try/finally` вокруг сетевого вызова + обработчики SIGINT/SIGTERM,
  которые после очистки завершают процесс с кодом сигнала; python — `try/finally` + обработчик
  SIGTERM, поднимающий `SystemExit`.
- Значения allowlist (возможен токен в строке `!helper`, `credential.*.username`) и значения
  residual-ключей (`http.proxy` может содержать `user:pass@`) не попадают в сообщения об ошибках
  и логи — только имена ключей и scope.

**Preflight helper для URL.** Собственная реализация url-match по правилам git (scheme, host с
wildcard, port, path-prefix при `useHttpPath`, порядок записей, сброс пустым значением) — одна
спецификация для mjs и python; оракул теста паритета — фактический `git credential fill` с
fixture-helper (печатающим маркер, без секретов) на тех же конфигах, включая wildcard-хост и
`useHttpPath`.
- Новая логика mjs — в `bd-git-environment.mjs` только на builtins Node (closure pre-push guard,
  `RUNTIME_FILES`/`SOURCE_FILES` в `bd-publisher-setup.mjs:20-28`, `bd-apply-intents.sh:24,40`,
  `.agents/distribution-manifest.json` не меняются по составу; если меняются — обновляются).

**Интерактивность.** `GIT_TERMINAL_PROMPT=0` остаётся: терминальный запрос пароля невозможен.
Helper (osxkeychain, GCM, `gh auth git-credential`) ведёт себя так же, как при обычном `git push`
пользователя, включая возможное окно входа GCM при истёкшем токене — это поведение обычного push,
не новый ручной шаг. Caller `SSH_ASKPASS`/`GIT_ASKPASS` сбрасываются (как сейчас, `GIT_*`).

**Граница доверия (ADR §3.39).** Пользовательский config (HOME/XDG, system, встроенный Apple Git)
доверен **только** для allowlist. `!cmd` helper исполняется в trusted publisher route так же, как
при обычном push пользователя. `commit-tree` снимка получает тот же перенос (включая
`credential.*`) — безвредно, отмечается в ADR. `url.*.insteadOf`/`pushInsteadOf`, `alias.*`, `core.hooksPath`,
`core.sshCommand`, `include` вне allowlist не переносятся; URL origin — только из local config.

**Seam для тестов.** Тесты задают fixture `HOME` + `XDG_CONFIG_HOME`; для scope `system`/
`unknown` и для пустого источника — внедряемый reader (параметр функции в mjs и python,
переменная-override в shell). Override проходит те же allowlist и правила scope, что и настоящий
reader, поэтому худший случай равен контролю caller над HOME; отдельного «тестового режима» нет.
Тест `bd-publisher-setup.test.mjs:93-94` превращается в: изолированный HOME + пустой reader → по-прежнему throw; новый позитивный кейс helper в
fixture global → проходит; spoof `GIT_CONFIG_GLOBAL` (100-104) по-прежнему игнорируется.

Отклонённые варианты:
- *Ручной `git config --local credential.helper`* — отклонён оператором.
- *Автоматически записывать helper/identity в repo-local config при setup* — снимок устаревает при
  смене входа, меняет config пользователя без запроса, не покрывает legacy route и installer.
- *Снять изоляцию global/system целиком* — возвращает insteadOf/alias/hooks.
- *`GIT_CONFIG_COUNT`* — command scope перекрывает local.
- *Читать `git config --global`/`--system`* — теряет встроенный Apple config (osxkeychain) и
  `includeIf hasconfig`/`gitdir` (проба Reviewer).

## Scope / non-goals

IN: файлы inventory и общие helpers; preflight publisher/activation; их тесты
(`scripts/tests/bd-*.test.*`, `scripts/test-bd-sync.sh`, `scripts/tests/install-*.test.py`);
`.agents/HOW_TO_USE.md`, `.agents/INSTALL.md` (контракт); ADR §3.39 + `docs/architecture/ADR-INDEX.md`;
CHANGELOG; migration notes.

OUT: SSH route; Windows gate (PR #19); перерегистрация publisher установленных проектов.

**Residual (не в allowlist; задачи Beads, диагностика без ручного шага):** `http.*` (proxy, CA,
`sslBackend=schannel` в system config Git for Windows), global `url.<ssh>.insteadOf` и
`core.sshCommand`, `author.*`/`committer.*`, `commit.gpgSign` при обязательной подписи. Если
обычный push пользователя зависит от них, маршрут падает с диагностикой, называющей ключ и задачу.
Перечень раскрывается в PR оператору как ограничение охвата аудитории.

Migration: копия `bd-git-environment.mjs` в controlDir pre-push hook остаётся старой до
перерегистрации — безвредно (guard только читает локально; `sourcePins` сверяются при setup).

Координация с PR #19: оба в rc.5.2 и трогают CHANGELOG/Memory Bank; ADR — §3.38 (#19) и §3.39
(#20). PR, влитый вторым, делает rebase и разрешает конфликты в этих файлах. Release выпускает PM
после merge обоих (или готового).

## Шаги

1. **Inventory (RED).** Тест-таблица маршрутов выше: каждый сетевой вызов идёт через network env,
   прочие — чистая изоляция.
2. **RED reader/перенос.** Fixture: HOME/XDG с global (`credential.helper` в форме `gh auth
   setup-git` с пустым сбросом, `credential.https://github.com.helper`, user.*, `url.*.insteadOf`,
   `alias.*`, `core.hooksPath`, `include.path`, `includeIf gitdir`, `includeIf hasconfig`) +
   reader-seam со scope `system`/`unknown` (osxkeychain). Ожидание: helper-список и identity как у
   обычного git в том же repo; insteadOf/alias/hooksPath не видны; caller `GIT_CONFIG_GLOBAL`
   игнорируется; унаследованный `GIT_CONFIG_NOSYSTEM=1` не сужает источник (B-09). Shell, mjs,
   python (паритет).
3. **RED preflight.** Точная форма конфига оператора (url-scoped пустой сброс + `!gh auth
   git-credential` + osxkeychain `unknown`) проходит; URL, для которого остаётся только пустой
   `helper =`, → fail-closed; нет identity → прежнее сообщение.
4. **ADR §3.39** (до кода шага 5).
5. **Fix** helpers, маршрутов, preflight, installer.
6. **Lifecycle (B-07).** После успеха, ошибки и SIGINT временного файла нет; права 0700/0600;
   на Windows — native-путь.
7. **Живые проверки** (B-01, B-08). HOW_TO_USE/INSTALL, CHANGELOG, Memory Bank.
