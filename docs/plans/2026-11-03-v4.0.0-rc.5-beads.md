# OverGate v4.0.0-rc.5 — план

## 0. Цель и исходные решения

Оператор 2026-11-03 запросил быстро довести rc.4 до теста на новом проекте и обновить работу
с Beads по полезным результатам U2. Отдельным ответом оператор перенёс WI-2 `og-7sr`
(сложные пути и Bash recovery) из rc.4 в rc.5. Это решение [записано в PR #12](https://github.com/komleff/overgate/pull/12#issuecomment-6610011508).

**Цель rc.5:** агент в новом проекте самостоятельно готовит, публикует и подтверждает операции
Beads через доверенный publisher; следующий агент или другая авторизованная машина читает тот
же опубликованный результат. Установка и первый запуск не теряют прежнюю или pending работу.
Оператор по-прежнему выбирает product WHAT и делает merge кода; task operations не становятся
его обязательной ручной работой. `--no-beads` сохраняется. Первый install PR сначала несёт
проверенный код; task publisher активируется из trusted target `main` после operator merge.

**База для планирования:** OverGate PR #12 `de552856` (rc.4 WI-1, ещё не merged/released).
Кодовый upstream: U2 [PR #913](https://github.com/komleff/u2/pull/913), merged
`13043590f` с helper source `3ab477633`; authority — [ADR-0072 v1.1](https://github.com/komleff/u2/blob/13043590f/docs/architecture/ADR-0072-Beads-Agent-Publication-Across-Authorized-Checkouts.md).
[Операционная приёмка 01.11](https://github.com/komleff/u2/pull/913#issuecomment-6546476723)
подтвердила Win/Mac публикацию и взаимный read-back; [адресное восстановление](https://github.com/komleff/u2/pull/913#issuecomment-6547940121)
закрыло разрешённый Stage1. Это доказательство U2, не OverGate acceptance. Исключённый
исторический остаток U2 (`tracks`, competing notes/time) не переносится в generic reference.

Режим **CRITICAL**: общая task authority, сохранность данных, migration и governance.
Открыть Draft PR с планом и Verification Contract; независимый Plan Review → `PLAN_READY`
до реализации. Один implementer, QA по AC, один scoped Code Review; budget 6 verifier launches
на каждый самостоятельный work item. Каждому verifier дать AC/FAIL/named risk.

## 1. Target → as-built → gap

| Surface | OverGate rc.4 | U2, полезный перенос | Target rc.5 |
|---|---|---|---|
| Task lifecycle | Reader + `bd-wt.sh`; cloud `.bd-intents/` применяет оператор, applier не поставляется | Агент создаёт/claim/update/close, публикует и читает ID/SHA; `tmp:` не результат | Агент завершает публикацию сам; при недоступном writer сохраняет typed queue и точный blocker |
| Publishers | Один основной checkout, legacy snapshot export/restore | Несколько авторизованных checkout, local lock + non-force CAS, independent Win/Mac read-back | Generic multi-checkout route; Git tree type не считается межмашинной авторизацией |
| Queue/retry | Документирован пример v1 intents, нет shipped executor | Typed v2 + frozen base/actor, payload hash/preconditions, durable outcome ledger, replay/recovery | Переносимый контракт и trusted helpers с replay и явными конфликтами |
| Integrity | last-seen/drop guard; `restore-before-export` может перекрыть pending state | Full-object fidelity, fail-closed fetch/parse, continuity, no last-write-wins | Новый managed writer сохраняет supported поля, comments/memories/edges и pending work |
| Install | `bd-bootstrap.sh` делает `bd init` и первый legacy export из install-ветки | Bootstrap/preservation до первого managed write; CLI квалифицируется по bytes/capabilities | Install PR доставляет код; после operator merge managed activation из trusted target `main`; upgrade rc.4 только после preservation/adoption |
| Identity/policy | Beads route в AGENTS template/HOW_TO_USE указывает operator applier | `agent-UUID`, подтверждённый `claim`, published SHA/read-back до deliverables | Generic правила в owner/adapter; project prefix и пути задаёт проект |
| Recovery path | `og-7sr` открыт | Не относится к Beads | Отдельный WI-2 rc.5; общий релиз после него либо отдельное решение оператора |

## 2. Границы переноса

**Внести:** U2 typed operation/schema, preconditions, shared outcomes, fresh temporary CLI store,
strict snapshot fidelity, durable pending/retry, non-force compare-and-swap publication,
linked worktree/isolated queue routes, publisher setup/guard и first-transition checks.
Использовать frozen U2 files как source map, но адаптировать по generic contract и проверять
каждый changed blob: `scripts/bd-apply-intents.sh`, `scripts/bd-publisher-setup.mjs`,
`scripts/lib/bd-{apply-engine,managed-cli,managed-contract,managed-entry,managed-git,managed-journal,managed-transaction,publisher-push-guard,snapshot}.mjs`, reader/worktree/sync wrappers,
`.bd-intents/README.md` и их tests.

**Обезличить:** `U2-...` regex, `u2.beadsPublisher`/`u2.beadsCli`, `u2-bd-managed` и
`.beads/u2-*.json`, U2-specific recovery pin `4da59682`/snapshot SHA, project paths, U2
claims/epics и конкретные CLI binary fingerprints. Project prefix читается из verified
Beads metadata/конфига и закрепляется в локальном publisher state; несовпадение или смена
prefix — stop. Формат generic protocol должен быть versioned; старый U2 ledger не объявлять
совместимым простой заменой имён. `APPROVED_REPAIR` — одноразовое исключение U2, не feature.

**Не переносить:** product/game data, реальные U2 task records, личные credentials/settings,
исторический restore author/time, unsafe force/skip-sync overrides, автоматическую установку
или миграцию CLI. Не запускать PR-branch code как publisher. Сохранять project-owned AGENTS,
Beads rules и custom hooks; conflict показывать до записи.

## 3. Поставка по самостоятельным work items

### WI-A — generic managed protocol и trusted publisher

1. Зафиксировать generic ADR после §3.33 и заменить старую модель только для managed mode.
   Existing rc.4 route остаётся явным legacy до безопасного перехода. Согласовать source/owner
   `AGENTS` template, `.agents/HOW_TO_USE.md`, `.agents/INSTALL.md`, `.claude/rules/beads.md`.
2. Перенести contract/engine/CLI/journal/Git snapshot/push guard, typed queue v2 и setup helper.
   Format и paths выбираются по версии протокола и verified project prefix. `bd-read.sh` и
   `bd-wt.sh` работают из primary, linked worktree и isolated reader без прямой Dolt-записи.
3. Synthetic tests: two independent clones/actors, concurrent unrelated vs same-field edits,
   lost receipt, failed push, zero-mutation retry, replay после reopen/reassign, corrupt/missing
   snapshot, unsupported payload, stale CLI, wrong prefix, old writer downgrade. No raw JSONL
   edit или silent last-write-wins.
4. Проверить native `bd` на disposable Windows/macOS/Linux проектах. Production writer каждой
   платформы разрешить только после qualified exact binary fingerprint + supported-field
   round-trip; version/help недостаточны. Отсутствие Linux proof блокирует выпуск rc.5,
   поскольку QUICKSTART заявляет Linux. Reader/prepare доступны без writer capability.

Deliverable: reviewed generic publisher можно вызывать из доверенного основного checkout;
никакая установка проекта пока не переключена на него автоматически.

### WI-B — installer, fresh project и безопасный upgrade

1. Добавить closure WI-A в `.agents/distribution-manifest.json`, `check-reference.py`,
   installer plan/apply/rollback и tests. `--no-beads` исключает весь Beads closure; Memory Bank,
   project verifier и main protection по rc.4 не меняются. Tracked install-state получает
   versioned `beads_protocol: managed-v1 | legacy-v0 | none`: значение означает выбранный
   protocol, не факт activation. Для fresh Beads target — `managed-v1`.
2. До `apply` в любом target (включая fresh OverGate install в существующий project) проверить
   `.beads`/Dolt metadata, `origin/beads-backup`, `.bd-intents/`, local receipts/queues и
   зарегистрированных writers. Ошибка чтения remote ≠ отсутствие branch. Существующее или
   неизвестное state → fail-closed с inventory/preservation packet; нельзя считать target
   пустым, делать `bd init`/restore или публиковать первый managed snapshot.
3. Fresh пустой target: install PR доставляет managed helpers и `beads_protocol: managed-v1`,
   но до operator merge не выполняет `bd init` и не пишет `beads-backup`. После merge агент
   запускает `bd-activate.sh` **из target main**, сверяет trusted exact helper closure,
   локальный/remote empty inventory и qualified CLI, делает `verified-absent` bootstrap,
   затем первую typed create→claim→publish→read-back. Initial install PR может жить без
   Beads ID; это узкая bootstrap граница, не право отложить обычную задачу с `tmp:`.
   U2-style `origin/main` trust guard поэтому видит merged helpers до первой публикации.
4. Upgrade rc.4 project: `legacy-v0` сохраняется до явной activation. Инвентаризовать remote
   R, локальную БД, старые queues/receipts, config/hooks и writer machines. Unknown/pending
   state → stop с preservation packet; не делать `restore` поверх pending, не переписывать
   `.beads/dolt`. Подтверждённый clean/pending-retained путь: immutable artifacts + SHA256 +
   frozen R, rehearsal, activation по доверенному helper после operator merge, rollback только
   до первой managed publication. Тот же inventory gate применяется и к fresh install в
   project со старым Beads, без автоматической конверсии.
5. Согласовать переход всех авторизованных publishers; старый writer блокируется guard до
   managed publication. Durable ledger/markers не может быть удалён старым export. Установка
   в одном clone не выдаёт полномочие другому и не меняет personal Git config без плана.
6. Обновить `QUICKSTART`, README/INSTALL/HOW_TO_USE, template и CHANGELOG для свежего проекта:
   агент сам ведёт задачи; при недоступном publisher показывает queue/base/actor и конкретное
   действие, не отправляет оператора вручную применять каждую задачу.
7. Target QA: clean new project на Windows/macOS/Linux, Claude/Codex fresh sessions, отдельные
   authorized clones, linked worktree и isolated writer-unavailable; затем upgrade rc.4
   disposable fixture. Проверить pre-merge no-write, post-merge trusted activation,
   installer byte/rollback и настоящий publication SHA/read-back.

Deliverable: rc.5 source ставится в новый проект; managed task route доступен после operator
merge install PR и trusted activation. Upgrade старого проекта проходит только через доказанный
preservation/activation route. Нет silently migrated state.

### WI-C — `og-7sr` (отдельный план)

Переносимое Bash recovery для путей с пробелами/кириллицей и нормализация внутренних prefixes.
Своя ветка/PR, Plan Review и Verification Contract; native Windows + macOS проверки. Это не
часть Beads implementation. Решение оператора о переносе в rc.5 не объявляет WI-C выполненным.

## 4. Verification Contract

| AC | Условие принятия | Метод |
|---|---|---|
| AC1 | Fresh install PR не делает Beads write; после operator merge trusted target main activation даёт create→claim→update→close, настоящий project ID, `published_sha`, `claims.confirmed` и peer read-back | Native Win/Mac/Linux + two synthetic clones |
| AC2 | До изменений deliverables агент подтверждает current `in_progress`/свой `agent-UUID`/claim; `tmp:` и local CLI success не равны владению | Fresh Claude/Codex scenarios + negative cases |
| AC3 | Concurrent unrelated edits сохраняются; same-field/claim/graph conflict сохраняет обе queues и даёт адресный отказ, без force/LWW | Deterministic two-clone race |
| AC4 | Failed push/restart/lost receipt и retry той же prepared queue публикуют один outcome; старый close/update после reopen/reassign не применяется снова | Failure injection + shared ledger read-back |
| AC5 | Snapshot переносит supported fields, nested IDs, comments, memories, labels, typed edges без потерь; invalid fetch/parse/partial history/unknown fields не принимаются как empty | Disposable CLI round-trip, full-object comparison, fault injection |
| AC6 | Unknown CLI fingerprint, wrong prefix, untrusted PR helper, stale writer/downgrade и non-force race блокируются до task mutation/publication | Negative fixtures + publisher guard |
| AC7 | Fresh installer closure полон и byte-exact; `--no-beads` не ставит closure; versioned protocol state и project-owned files/settings/hooks сохранены; rollback не удаляет task state | Fresh/upgrade/rollback fixtures |
| AC8 | Любой target с legacy/pending/unknown state (включая fresh OverGate install в старый Beads project) стопорится до записи; rc.4 upgrade сохраняет bytes/artifacts и требует explicit preservation | Disposable migration rehearsal + negative cases |
| AC9 | Windows/macOS/Linux qualified writer, primary/linked/isolated routes дают подтверждённый результат либо конкретный technical blocker; operator не routine task applier | Native sessions + peer read-back |
| AC10 | `bash scripts/verify-reference.sh` на final HEAD, CI Linux/macOS/Windows, installed project verifier и trusted finalize пройдены; `NOT RUN` остаётся отдельным статусом | Exact SHA logs/PR evidence |

**Инварианты:** non-force publication, supported-state preservation, immutable operation ID/payload,
project-owned authority, trusted main tooling, no automatic real migration, operator-only code
merge. Достаточно одной финализации final HEAD после landing/fresh checks. Evidence по WI-A/B
с exact SHA, AC, paths, content fingerprint, `PASS | FAIL | NOT RUN` и named risks в PR.

**Named risks:** R1 silent data loss/old writer downgrade; R2 duplicate or stale task replay;
R3 unverified CLI serialization; R4 prefix/identity collision across projects; R5 installer
switch before preservation; R6 misleading success without published read-back; R7 Windows/Unix
path or hook differences; R8 governance self-certification. Каждый blocker требует affected QA
и scoped re-review, не нового полного цикла. Не принимать реальный Important/Critical risk за
оператора.

## 5. Порядок и release boundary

1. Довести WI-1 rc.4 PR #12 до полного acceptance и trusted finalize; merge/tag/release
   выполняет оператор. `og-7sr` перенесён в rc.5 отдельным решением.
2. WI-A Draft PR → independent PLAN_READY → implementation/tests → QA → scoped review →
   trusted finalize → operator merge. Прежде установленный project writer не переключать.
3. WI-B Draft PR на trusted WI-A → тот же lifecycle, target project QA и migration rehearsal.
   Не начинать real rc.4 project adoption без отдельного разрешённого scope.
4. WI-C `og-7sr` по отдельному плану. После merge всех WI — fresh exact-HEAD regression,
   affected recheck по изменённым поверхностям, один release acceptance на конечном SHA.
5. Оператор публикует `v4.0.0-rc.5` prerelease; stable Latest остаётся `v3.9.0` до отдельного
   решения. Новый проект тестируется сначала по точному rc.4 SHA для installer/UX, затем по
   rc.5 только после verified managed publisher activation.

**Rollback:** До первой managed publication восстановить tracked managed bytes через installer
snapshot, локальные publisher registration/hooks через reviewed setup rollback, исходный Beads
backend оставить нетронутым. После публикации не откатывать на старый writer; сохранить ledger,
queues и snapshot, остановить запись и выполнить адресное восстановление через новый reviewed
plan. Ни release rollback, ни revert к старому export не должны удалять shared outcomes.
