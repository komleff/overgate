# OverGate v4.0.0-rc.4 — план

**Цель:** коллега без контекста U2 ставит OverGate в свой проект по быстрому старту, получает
безопасные настройки по умолчанию и может работать без Beads. Windows и сложные пути проверены
вживую.

**Решения оператора 2026-10-24:**
- свежая установка в проект без своих настроек получает профиль `guarded`; нынешнее поведение —
  профиль `autonomous`, только явным флагом;
- установщик получает режим `--no-beads`;
- живую проверку на Windows выполняет оператор по чек-листу §5.4;
- og-7sr входит в rc.4.

**Повод:** пробная установка rc.2 на чистый проект и разбор готовности (сессия PM 2026-10-24).
Fresh install копирует рабочий `.claude/settings.json` эталона: `defaultMode: bypassPermissions`,
`allow: Bash(*)`, `skipDangerousModePermissionPrompt`, `skipAutoPermissionPrompt`,
`language: russian`, deny `docker-compose.prod.yml` (остаток U2). Существующие настройки проекта
установщик уже сохраняет: проверено на проекте со своим `settings.json`.

**Режим:** CRITICAL. Установщик пишет permissions каждого установленного проекта; меняется
triage parser `finalize-pr` (pipeline governance, PM_ROLE §10).

**Состав.** Два work item, у каждого свой Draft PR, Plan Review, QA, Code Review и budget 6:
- **WI-1 (этот план):** профиль настроек, `--no-beads`, install-state, быстрый старт, чек-лист
  Windows — og-9ic.1, og-9ic.2, og-9ic.5, og-9ic.3, og-9ic.4.
- **WI-2:** og-7sr — переносимое восстановление Bash и нормализация runtime-префиксов. Отдельный
  план по AC og-7sr (native Windows + macOS). Здесь фиксируются только граница и порядок.

Release `v4.0.0-rc.4` выпускается после merge обоих.

**База.** `main` после merge rc.3 (og-7d1, PR #11). До merge rc.3 ветка от `073595a` (rc.2)
содержит только план. Код пишется после rebase на rc.3 и `PLAN_READY`.

## 2. Решения HOW

### 2.1 Профиль `guarded` (P1)

- Отдельный reviewed source-файл `.agents/templates/settings.guarded.json`, а не вычисление на
  лету: побайтная проверка fresh остаётся простой.
- Содержание:
  - `hooks` побайтно равен блоку source `.claude/settings.json`;
  - `deny` = deny source без остатка U2 `docker-compose.prod.yml`;
  - `env` — только `PYTHONIOENCODING`;
  - нет `defaultMode`: Claude работает в штатном режиме с подтверждениями;
  - нет `skipDangerousModePermissionPrompt`, `skipAutoPermissionPrompt`, `language`;
  - `allow` — только read-only команды: `Bash(git status*)`, `Bash(git diff*)`, `Bash(git log*)`,
    `Bash(gh pr view*)`, `Bash(gh pr checks*)`.
- `check-reference.py` эталона проверяет: hooks guarded == hooks source; deny guarded ⊇ deny source
  минус задокументированные исключения. Расхождение = FAIL, иначе guarded отстанет от source.
- `plan` записывает профиль в план и печатает его. Для `autonomous` — одна строка
  предупреждения: «bypassPermissions: агент выполняет команды без подтверждения».
- Upgrade: профиль берётся из install-state. `--profile`, отличный от записанного, — stop с
  адресным сообщением; смена профиля — отдельное решение в target PR. Install-state rc.1–rc.3
  без поля профиля читается как `autonomous`.
- Проект со своими settings: профиль не применяется к permissions и mode; `plan` печатает
  «permissions проекта сохранены».
- Сам эталон OverGate остаётся на своих рабочих настройках (`autonomous`).

### 2.2 Режим `--no-beads` (P2)

- Manifest: у 8 Beads-entries поле `"component": "beads"`; `--no-beads` их исключает. Прочий
  формат manifest не меняется.
- AGENTS template: Beads-абзац между маркерами `<!-- overgate:beads -->` и
  `<!-- /overgate:beads -->`. В `--no-beads` блок вместе с маркерами не пишется.
- Deny `bd delete*`, `bd dolt push*` и прочие остаются: в проекте без bd они безвредны.
- `finalize-pr`: triage `defer` принимает Beads ID либо ID трекера проекта (`#123`, URL issue).
  Пустое или мусорное значение по-прежнему блокирует. Это изменение governance-skill: по
  PM_ROLE §10 WI-1 финализируется `finalize-pr` из rc.3, а не своей новой версией.
- `check-reference.py` в target: Beads-пути обязательны только при `beads: true` в install-state.
- Upgrade: режим берётся из install-state; смена режима — stop. Install-state rc.1–rc.3 читается
  как `beads: true`.

### 2.3 install-state (P3)

- Tracked: source SHA, версия manifest, профиль, режим Beads, относительные target-пути, хеши.
  Абсолютных путей нет.
- Абсолютный путь backup остаётся в ignored `.overgate-backups/<id>/rollback.json`; `rollback`
  и так принимает `--backup` явно.
- Upgrade читает install-state rc.1–rc.3 с абсолютными путями и пишет новый формат. Rollback
  возвращает прежние байты install-state.

### 2.4 `QUICKSTART.md` (P4)

Файл в корне эталона, в manifest не входит. Не длиннее 150 строк, термины пайплайна поясняются
при первом упоминании. Разделы:
- для кого: один оператор на проект, Claude Code, macOS/Linux (Windows — после §5.4); командная
  работа в одном репозитории — не основной сценарий;
- что понадобится и как проверить;
- установка за 5 шагов, профили `guarded`/`autonomous`, `--no-beads`;
- что появится в проекте;
- почему коммит блокируется до заполнения `.agents/project/verify.sh` и как его заполнить;
- первый PR на примере FAST-задачи: план → реализация → проверка → finalize → merge оператора;
- откат и известные ограничения.

### 5.2 Инварианты

- conflict-политика, порядок операций, backup и rollback не ослабляются; нет `--force`;
- permissions и mode проекта со своими settings не меняются ни в каком профиле;
- `autonomous` = байты source;
- hooks в `guarded` и `autonomous` идентичны: защита не зависит от профиля.

### 5.3 Named risks

- R1 — guarded отстаёт от source, например новый hook появился только в source (AC-04).
- R2 — upgrade старой установки меняет профиль или permissions (AC-03, AC-06).
- R3 — ослабление triage parser `finalize-pr`: `defer` с мусором проходит (AC-09); самосертификация
  исключена финализацией через rc.3.
- R4 — `--no-beads` ломает хуки или скиллы, которые ждут bd (AC-07; grep bd по runtime-поверхности).
- R5 — новый формат install-state ломает upgrade или rollback (AC-06, AC-10).
- R6 — guarded слишком строгий, агент спрашивает на каждом шаге. Не blocker rc.4: покажет пилот
  og-9ic.7, read-only allow расширяется отдельным решением.

### 5.4 Чек-лист живой проверки на Windows (оператор, og-9ic.4)

Окружение: Windows 10/11, Git for Windows (Git Bash), Python через `py -3`, Claude Code. Два
проекта: `C:\work\demo` и путь с пробелом и кириллицей `C:\Users\<user>\Мои проекты\demo app`.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `git clone` OverGate, checkout candidate SHA | чистое дерево |
| 2 | `plan` → `apply` без флагов в чистый проект | профиль `guarded`, conflicts 0; `check-reference` PASS; `verify.sh` → NOT CONFIGURED |
| 3 | Claude Code из корня проекта | подтверждение загрузки хуков |
| 4 | Попросить агента выполнить `ls` и записать файл | `ls` проходит; запись спрашивает подтверждение |
| 5 | `git push origin main`, `gh pr merge 1`, `gh pr comment 1 --body "ready to merge"` | все три заблокированы хуком |
| 6 | `git commit` до и после заполнения `verify.sh` | до — блок; после — коммит проходит |
| 7 | Повторить шаги 2, 4, 5 для `--no-beads` и `--profile autonomous` | Beads-файлов нет; в autonomous запись без подтверждения, блокировки те же |
| 8 | `rollback` | проект как до установки |

Evidence в PR WI-1: таблица «шаг | ожидание | факт | лог или скриншот», версии Windows, Git,
Python и Claude Code, путь проекта. Случаи восстановления og-7sr проверяются в плане WI-2.

## 6. Rollback

Revert PR до релиза. После публикации — отзыв в описании release и rc.5; тег не двигать.
Проект, установленный rc.4, откатывается `install-overgate.py rollback`: журнал хранит прежние
байты settings и install-state.
