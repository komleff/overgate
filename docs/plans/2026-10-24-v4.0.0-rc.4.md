# OverGate v4.0.0-rc.4 — план

**Целевая аудитория (оператор, 2026-10-24):** люди без опыта программирования, управления
проектами, тестирования и развёртывания. Агенты работают самостоятельно; человек ставит задачу,
принимает результат и нажимает merge. Запрос подтверждения на каждое действие такой аудитории не
помогает: она не может оценить, на что агент просит разрешение. Защита должна быть встроена в
процесс и не зависеть от суждения оператора.

**Цель:** коллега-неспециалист поручает агенту установить OverGate в свой проект по быстрому
старту. Агенты работают без вопросов, main защищён и локально, и на GitHub. Memory Bank и Beads
созданы и готовы к работе сразу после установки: без них агенты не ведут продукт автономно между
сессиями. Для разовых проектов есть режим без Beads. Windows и сложные пути проверены вживую.

**Решения оператора 2026-10-24:**
- режим агента в новом проекте — `auto` (классификатор Claude Code отсекает опасное без вопросов
  оператору); запасной вариант для аккаунтов без `auto` — флаг `--mode bypass`;
- защиту main на GitHub включает агент при установке;
- Memory Bank и Beads обязательны для автономной работы над продуктом: установка создаёт каркас
  Memory Bank и инициализирует Beads; режим `--no-beads` остаётся для разовых проектов, Memory Bank
  создаётся и в нём;
- при upgrade установка с неправленными settings (по смыслу равны известному прежнему source
  rc.1–rc.3) переводится на settings rc.4; settings с правками проекта сохраняют свой режим;
  og-1oh (артефакт rc.2 в конфиге Codex) закрывается тем же механизмом в WI-1;
- живую проверку на Windows выполняет оператор по чек-листу §5.4 на основном Windows-ПК разработки;
- og-7sr входит в rc.4.

**Повод:** пробная установка rc.2 на чистый проект и разбор готовности (сессия PM 2026-10-24).
Fresh install копирует рабочий `.claude/settings.json` эталона: `defaultMode: bypassPermissions`
отключает и встроенную страховку Claude Code; deny содержит остаток U2 `docker-compose.prod.yml`.
Хуки защищают main только в локальной сессии, на GitHub защиту никто не включает. Существующие
настройки проекта установщик сохраняет: проверено на проекте со своим `settings.json`.

**Режим:** CRITICAL. Установщик пишет permissions каждого установленного проекта; меняется
triage parser `finalize-pr` (pipeline governance, PM_ROLE §10).

**История версий плана:**
- v0.2 — граница Windows: runtime U2 ежедневно работает на Windows-ПК оператора, CI
  `windows-native` покрывает dispatcher и установщик; не подтверждены только живая сессия в
  проекте, установленном OverGate, и новые режимы rc.4.
- v0.3 — профиль `guarded` (подтверждения по умолчанию) отменён оператором как несовместимый с
  целевой аудиторией. Вместо него: режим `auto`, запасной `--mode bypass`, защита main на GitHub
  (og-9ic.8). Добавлены каркас Memory Bank и инициализация Beads (og-9ic.9): в rc.2 установленный
  PM_ROLE первым шагом читает `.memory-bank/activeContext.md`, которого установщик не создаёт, а
  шаг `bd init` из INSTALL v3.9 §B.5 в v4 потерян.
- v0.4 — rc.3 смержен (`b830d5e`, тег `v4.0.0-rc.3`). `merge_settings` rc.3 переносит из source
  только hooks и deny (объединением) и не трогает `defaultMode`, поэтому без нового правила
  неправленные установки остались бы на `bypassPermissions` и потеряли бы побайтное соответствие.
  Добавлены: правило upgrade «известный прежний source → новый source», og-1oh, требование
  исполнимого гейта finalize (og-159).

  Не исполнился — stop и эскалация оператору, ручной обход не принимается. og-159 чинится

## 2. Решения HOW

### 2.1 Режим агента (P1)

- Рабочие настройки эталона `.claude/settings.json` переходят на `defaultMode: auto`; deny-остаток
  U2 `docker-compose.prod.yml` удаляется. Fresh = байты source, поэтому rc.3 AC-01 и правило записи
  rc.3 §4.2 сохраняются без отдельного шаблона.
- `--mode bypass` (для аккаунтов без `auto`): байты source с единственной текстовой заменой
  значения `defaultMode` на `bypassPermissions`.
- Прочие ключи (`allow`, `env`, `skip*`, `language`, hooks) не меняются: hooks не зависят от режима.
- Upgrade, правило «известный прежний source»:
  - manifest хранит канонические отпечатки (строгий по типам `json.dumps(sort_keys=True)`, как в
    rc.3) Claude settings source rc.1, rc.2 и rc.3;
  - target по смыслу равен одному из них → settings не правились → пишутся байты нового source
    (`auto`) либо bypass-вариант при `--mode bypass`; `plan` печатает смену режима;
  - иначе → merge rc.3 без изменений: permissions и `defaultMode` проекта не меняются, deny
    дополняется объединением; `--mode` в этом случае → stop с указанием на ручную правку в target PR.
  Пример: u2-lab с четырьмя project allow-правилами сохраняет свой режим; без них — переходит на
  settings rc.4.
- Codex (og-1oh): известный артефакт rc.2 в `.codex/hooks.json` — пустой `permissions.deny` при
  отсутствии `permissions` в source — распознаётся и снимается; если после этого target по смыслу
  равен source → байты source; custom-ключи Codex сохраняются.
- Доступность `auto` зависит от аккаунта и версии Claude Code, установщик её не проверяет.
  QUICKSTART и INSTALL объясняют, как понять, что `auto` недоступен, и как переключиться.
  Фактическое поведение Claude Code в этом случае фиксируется в AC-05 (R1).
- `plan` печатает выбранный режим одной строкой.

### 2.2 Защита main на GitHub (P2)

- Helper `scripts/og-protect-main.sh` (managed, вне Beads-набора): через `gh` определяет репозиторий
  и ветку по умолчанию, читает текущую защиту и добавляет недостающие правила: PR обязателен
  (0 approvals — оператор один), force push и удаление запрещены. Более строгие существующие правила
  не ослабляет; повторный запуск — no-op.
- Результат проверяется чтением через `gh api`. Нет `gh auth`, нет прав администратора или защита
  недоступна на тарифе (приватный репозиторий на бесплатном плане) — отдельный код выхода и одна
  строка для target PR; установка продолжается, ограничение пишется в PR и Memory Bank (R8).
- Шаг процедуры установки выполняет агент-установщик после `apply`.
- Developer проверяет, что guards не блокируют helper. Прямые `gh api`-записи в
  `/branches/*/protection` вне helper — R7; deny `gh api -X DELETE *` уже есть.

### 2.3 Memory Bank и Beads при установке (P3)

- Шаблоны `.agents/templates/memory-bank/` — `projectbrief`, `productContext`, `systemPatterns`,
  `techContext`, `activeContext`, `progress`: заголовки и подсказки, что писать. Manifest: policy
  `preserve`, target `.memory-bank/*.md` — файл создаётся, если его нет; существующий не трогается;
  upgrade не обновляет. Ставятся всегда, включая `--no-beads`.
- AGENTS template: строка про Memory Bank — читать перед задачей, обновлять `activeContext` и
  `progress`.
- Helper `scripts/bd-bootstrap.sh` (Beads-набор, managed) выполняет агент-установщик после `apply`:
  1. `bd` нет → stop с инструкцией установки для ОС; helper ничего не скачивает;
  2. база уже есть (`.beads/metadata.json`) → no-op и отчёт;
  3. иначе `bd init` без генерации agent-инструкций (в v3.9 — `--skip-agents`; флаг сверить с
     текущим `bd init --help`), embedded-режим, `export.auto=false`, `sync.remote` не задан;
  4. первый `bash scripts/bd-sync-export.sh` создаёт ветку `beads-backup`.
  Fail-closed на любом шаге, без `--force`.
- Поддерживаемый диапазон версий bd записан в manifest; вне диапазона helper останавливается с
  адресным сообщением (R9).

### 2.4 Режим `--no-beads` (P4)

- Manifest: у Beads-entries (8 из rc.2 и `bd-bootstrap.sh`) поле `"component": "beads"`;
  `--no-beads` их исключает. Прочий формат manifest не меняется. Memory Bank ставится.
- AGENTS template: Beads-абзац между маркерами `<!-- overgate:beads -->` и
  `<!-- /overgate:beads -->`; в `--no-beads` блок вместе с маркерами не пишется.
- Deny `bd delete*`, `bd dolt push*` и прочие остаются: в проекте без bd они безвредны.
- `finalize-pr`: triage `defer` принимает Beads ID либо ID трекера проекта (`#123`, URL issue).
  Пустое или мусорное значение по-прежнему блокирует. По PM_ROLE §10 WI-1 финализируется
  `finalize-pr` из rc.3, а не своей новой версией.
- `check-reference.py` в target: Beads-пути обязательны только при `beads: true` в install-state.
- Upgrade: режим берётся из install-state; смена режима — stop. Install-state rc.1–rc.3 читается
  как `beads: true`.

### 2.5 install-state (P5)

- Tracked: source SHA, версия manifest, режим агента, режим Beads, относительные target-пути, хеши.
  Абсолютных путей нет.
- Абсолютный путь backup остаётся в ignored `.overgate-backups/<id>/rollback.json`; `rollback`
  и так принимает `--backup` явно.
- Upgrade читает install-state rc.1–rc.3 с абсолютными путями и пишет новый формат. Rollback
  возвращает прежние байты install-state.

### 2.6 `QUICKSTART.md` (P6)

Файл в корне эталона, в manifest не входит. Не длиннее 150 строк, написан для человека без опыта
программирования; термины поясняются при первом упоминании. Разделы:
- для кого: один оператор на проект, Claude Code; Windows (Git Bash), macOS, Linux; агенты
  работают сами, человек ставит задачу, принимает результат и нажимает merge;
- что понадобится и как проверить;
- одна фраза-поручение агенту на установку. Агент сам выполняет установку, заполняет
  `.agents/project/verify.sh` тестами проекта (если тестов нет — создаёт минимальные), включает
  защиту main, создаёт Memory Bank и Beads;
- режим `auto` и запасной `--mode bypass`; `--no-beads` для разовых проектов;
- что появится в проекте и зачем;
- первый PR на примере FAST-задачи: задача → план → реализация → проверка → finalize → merge;
- откат и известные ограничения.

### 5.2 Инварианты

- conflict-политика, порядок операций, backup и rollback не ослабляются; нет `--force`;
- permissions и mode проекта со своими settings не меняются ни в каком режиме;
- hooks одинаковы во всех режимах: защита не зависит от режима агента;
- helpers не ослабляют существующую защиту main и не перезаписывают существующую базу Beads или
  Memory Bank.

### 5.3 Named risks

- R1 — `auto` недоступен на аккаунте коллеги: агент упирается в вопросы или ошибку (AC-05;
  QUICKSTART объясняет переключение на `--mode bypass`).
- R2 — settings с правками проекта ошибочно признаны «известным прежним source» и перезаписаны:
  потеря project allow/env (AC-03, AC-04; строгий по типам отпечаток).
- R3 — ослабление triage parser `finalize-pr`: `defer` с мусором проходит (AC-11); самосертификация
  исключена финализацией через rc.3, но только если гейт исполняется скриптом (AC-16, og-159).
- R10 — смена режима при upgrade на `auto` у аккаунта без `auto` останавливает работу агентов
  (AC-04, R1): `plan` печатает смену режима, QUICKSTART и INSTALL объясняют `--mode bypass`.
- R4 — `--no-beads` ломает хуки или скиллы, которые ждут bd (AC-09; grep bd по runtime-поверхности).
- R5 — новый формат install-state ломает upgrade или rollback (AC-04, AC-12).
- R6 — классификатор `auto` блокирует штатные действия пайплайна: push ветки, `gh pr create`,
  публикацию отчётов (AC-05). При блоке — запись в PR и решение оператора.
- R7 — агент ослабляет защиту main прямым `gh api` PUT. Проверка в Code Review; guard — следующая
  линия.
- R8 — защита недоступна на тарифе (приватный репозиторий на бесплатном плане): гарантия «merge
  только оператор» остаётся локальной. Явная запись в target PR, Memory Bank и QUICKSTART (AC-06).
- R9 — изменение CLI bd ломает bootstrap: диапазон версий, fail-closed (AC-08).

### 5.4 Чек-лист живой проверки на Windows (оператор, og-9ic.4)

## 6. Rollback

Revert PR до релиза. После публикации — отзыв в описании release и rc.5; тег не двигать.
Проект, установленный rc.4, откатывается `install-overgate.py rollback`: журнал хранит прежние
байты settings и install-state. База Beads, ветка `beads-backup` и защита main, созданные
helpers, rollback вслепую не снимает (как Beads и Memory Bank в INSTALL rc.2): это делается
отдельным решением в target PR.
