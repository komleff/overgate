# rc.5.2 — fail-closed guard, проходимый гейт коммита на Windows, вход Beads без ручной настройки

## Источник и решение оператора

Beads `og-5l6` (P0, security), `og-0pu` (P0), `og-4py` (P0), `og-1lg` п.1 (запас commit tier).

Оператор 2026-11-10 (дословно):
- при приёмке PR #18: «Принимаю og-5l6 и og-0pu: исправляем отдельным PR после merge #18.»
  (для og-5l6 ранее выбран вариант «Отдельный PR (Recommended)»);
- по og-4py, о требовании ручной настройки входа для синхронизации задач: «Это ручное говно, а
  не автоматический пайплайн! … Я твой процесс предлагаю своим коллегам как удобную автоматизацию»;
- о продукте: «Мне нужно починить … в принципе продукт overgate, который … могут копировать и
  использовать … хороший автоматизированный процесс».

Цель продукта (WHAT): у пользователя на macOS/Linux и на Windows 11 ru-RU агент Claude коммитит
через штатный гейт, защитный хук не пропускает опасные git-alias, Beads синхронизируется без
ручной настройки. Ручной шаг пользователя — дефект продукта.

**og-1lg п.1 включён в rc.5.2 (решение PM, HOW).** Без него AC-05 недостижим: живой Windows QA
оператора (PR #18, 854a840) — уже 27 из 34 шагов commit tier дали ≈536 с при пределе 570 с, без
самых долгих (`pre-bash-dispatch` и др.) и с рано упавшими тестами; на macOS commit tier 432 с
без нагрузки, под нагрузкой коммит плана дважды не прошёл гейт (timeout 569 с; flaky быстрая
фаза `pre-bash-dispatch` 13 с > 10 с). ROLE-001/002 (п.2–3 og-1lg) — вне scope.

Evidence: живой QA на ПК оператора (Windows 11 Pro 10.0.26200, ru-RU/cp1251, Git Bash 5.2.37,
git 2.51.2.windows.1, Python 3.14.0, `TMPDIR=/d/AI/Claude/tmp`):
[пошаговый отчёт](https://github.com/komleff/overgate/pull/18#issuecomment-6746529872) — 13 из 27
шагов commit tier FAIL; `repository-mutation-guard.test.sh` — 3 FAIL.

## Диагностика

Причины FAIL на Windows оператора собирает QA-агент оператора (Windows, роль QA, без правок) на
`b04b21c`: окружение (`where bash`, разрешение `bash` из Python, кодовые страницы), время шагов,
которых не было в отчёте PR #18, выдержки первых FAIL по шагам `with-timeout`,
`with-timeout-transparency`, `merge-gate-parse-budget`, `module-resolution-closure`,
`finalize-triage-parse`, `finalize-gate-script`, `publish-pr-comment`, `bd-node-path` и
классификация «без UTF-8 / с `PYTHONUTF8=1`» (только для диагностики, не как исправление).
Результат публикуется в PR; PM вносит установленные причины в таблицу gap до начала
исправлений по og-0pu. Исправления og-5l6 и og-4py от этой диагностики не зависят.

## Target → as-built → gap

## Шаги

1. **RED guard.** Кейсы: явный недоступный контекст (`--git-dir`, `GIT_DIR`, `-C`, `--work-tree`) с
   неизвестной подкомандой → block — краснеет на macOS/Linux сейчас. Модульный тест преобразования
   MSYS-пути для `nt` (подмена `os.name`/`cygpath`).
2. **Guard fix.** Перед alias lookup при явном контексте — `git rev-parse --git-dir` с тем же
   контекстом; отказ → GuardError (block). На `nt` — нормализация MSYS-путей контекста через
   `cygpath -w`; нет `cygpath`/ошибка → block.
3. **og-4py.** RED: fixture global/system config с `credential.helper`, `credential.<url>.helper`,
   `url.*.insteadOf`, `alias.*`, `core.hooksPath` → после sanitize helper виден, остальное нет
   (shell и mjs). Fix: прочитать `credential.*` из global/system (с include) после сброса
   caller `GIT_*`, передать через `GIT_CONFIG_COUNT/KEY_n/VALUE_n`; список разрешённых ключей
   один и проверяется тестом на обеих реализациях.
4. **Тесты commit tier на Windows.** `native_bash()` вместо `'bash'`; UTF-8 stdio; пути `TMPDIR`
   для нативных git/Python; остальные причины — по диагностике.
5. **Commit tier budget.** Время каждого шага в выводе `run()`. Шаги сверх бюджета переходят в
   full-уровень (остаются в `/verify` и required CI). Бюджет: commit tier ≤ 50 % предела (≤ 285 с)
   на macOS reference и ≤ 450 с в Windows CI. `verify-tiers.test.py` держит границу и полноту CI.
   Замер PM 2026-11-10 на macOS (`b04b21c`, load average 4–10): commit tier 502 с; крупные шаги —
   `pre-bash-dispatch` 126, `finalize-triage-parse` 67, `finalize-gate-script` 62, `with-timeout`
   39, `bd-wt` 38, `merge-gate-parse-complexity` 25, `readiness-policy-complexity` 23,
   `with-timeout-transparency` 22. Кандидаты в full (≈215 с): `finalize-triage-parse`,
   `finalize-gate-script` (финализация идёт только trusted route из main), `bd-wt` (Beads
   wrapper), `merge-gate-parse-complexity`, `readiness-policy-complexity` (замеры
   производительности, чувствительны к нагрузке машины). Guard, classifier, commit-gate,
   dispatcher и parser-тесты остаются в commit tier. Окончательный список — по таймингам Windows
   оператора (диагностика og-0pu); если бюджет не достигается без выноса guard/gate-тестов —
   стоп и решение оператора.
6. **Windows CI.** Джоба `windows-commit-tier`: Git Bash, без `PYTHONUTF8`, `TMPDIR` на `D:`,
   `bash .agents/project/verify.sh`; время в логе.
7. ADR, CHANGELOG, Memory Bank; release `v4.0.0-rc.5.2` после merge оператором.
