# OverGate v4.0.0-rc.3 — план

**Цель:** после установки или upgrade проект без собственных overrides побайтно соответствует
OverGate во всех managed- и settings-файлах, а повторная установка идемпотентна.

**Решение оператора 2026-10-24:** перед upgrade u2-lab выпустить `v4.0.0-rc.3` с исправлением
установщика. Нужно полное соответствие текущему OverGate, чтобы проверить его на реальном проекте.
Релиз — `prerelease=true`, `make_latest=false`.

**Повод:** Plan Review u2-lab PR #40 (https://github.com/komleff/u2-lab/pull/40#issuecomment-6371588124, B3) —
офлайн-моделирование установщика rc.2 на u2-lab.

**Режим:** CRITICAL — установщик меняет файлы guard'ов и настройки всех проектов. Budget 6.

**PR и база:** ветка `fix/installer-conformance` от `main` `073595a` (= rc.2), worktree
`overgate-wt-rc3`.

## 2. Scope

**IN:** `scripts/install-overgate.py` (C1–C3); `scripts/tests/install-distribution.test.py`;
`.agents/INSTALL.md` (поведение merge и ignore); версия `4.0.0-rc.3` во frontmatter и manifest,
README, CHANGELOG; при необходимости — `previous_rc_*` в manifest для известных прежних форм;
`.memory-bank/{activeContext,progress}.md`.

**OUT:** payload guards, dispatcher, bd-обёртки, skills; `og-jx3`, `og-m42`, `og-vjp`,
`og-7sr`, `og-bn6`, `og-mk4`; stable/Latest.

## 3. Шаги

1. RED: тесты-конформности до правки кода.
   - Fresh install в пустой проект: каждый managed- и settings-файл manifest побайтно равен source; `.gitignore` = фрагмент.
   - Upgrade из точной установки rc.1 и rc.2: то же побайтное равенство для проекта без overrides; `.gitignore` содержит фрагмент ровно один раз; `.codex/hooks.json` без `permissions`.
   - Повторный `plan` сразу после `apply`: нулевой diff записей.
   - Проект с own allow/deny/env/custom hook: они сохранены, недостающие managed deny добавлены, ключа нет там, где его нет ни в target, ни в source.
2. GREEN: C1–C3 в установщике, без изменения политики conflict и порядка операций.
3. Документы, версия, CHANGELOG, provenance-примечание.
4. Публикация после merge: тег `v4.0.0-rc.3` на merge SHA, release prerelease, Latest = `v3.9.0`.

**Инварианты:** conflict-политика, порядок операций, backup и rollback rc.2 не ослабляются; нет
`--force`; payload кроме установщика и документов не меняется.

**Named risks:**
- R1 — «равно по смыслу» ошибочно признаёт разные настройки равными. Метод: сравнение распарсенных объектов целиком, тест на различие в одном значении.
- R2 — идемпотентность `.gitignore` теряет project-строки или ломается на CRLF. Метод: тесты с project-строками до и после фрагмента и с CRLF.
- R3 — изменение serialization ломает существующие upgrade-фикстуры v3.9 и previous-RC. Метод: полный `install-distribution` и `verify-reference`.
