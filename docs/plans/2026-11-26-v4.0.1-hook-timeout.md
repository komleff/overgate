## 1. Проблема (target → as-built → gap)

**Target.** Медленное окружение замедляет агента, но не запирает его: команды чтения и диагностики
проходят; охраняемые операции (git/gh-мутации, коммит, публикация готовности) и всё, что может их
запустить, по-прежнему fail-closed. Сообщение называет вероятную причину и что делать.

**As-built (`v4.0.0`).**
- `.claude/hooks/pre-bash.sh` на КАЖДЫЙ Bash-вызов последовательно запускает
  `check-repository-mutation.py` и `check-merge-ready.py` (под `QUICK_LIMIT=10` через
  `with-timeout.sh`), запрос предела `check-tests-before-commit.sh --print-timeout-seconds` (тоже
  10 с) и сам гейт коммита. Код 124 → `block` (exit 2) с подсказкой
  `git -C <root> checkout -- .claude/hooks .claude/tools`.
- Гейт коммита классифицирует каждую команду (`commit_command_classifier.py classify-hook`) под
  `CLASSIFY_TIMEOUT_SECONDS=10`; RC 124 → exit 2.
- Mac оператора: macOS 26.5.2, Python 3.14; хуки исполняет `/bin/bash` 3.2.57
  (`command -v bash`). С 2026-11-25 iCloud «Рабочий стол и Документы» выгрузил
  `.claude/hooks/*.py`, `check-tests-before-commit.sh`, `.git/objects/**` (`dataless`).
  Guard на payload `ls` > 40 с; `pre-bash.sh` на `ls` → 11,1 с, exit 2. Агент не выполняет ни
  одной команды и перекладывает работу на оператора.
- ADR §3.32: «быстрые guards ≤ 10 с, таймаут = блок»; §3.38 принял «флакает под нагрузкой» как
  риск. Риск «полная блокировка агента» назван не был.

**Gap.** Таймаут быстрой фазы трактуется одинаково для `ls` и для `git push`; подсказка
восстановления ложная (файлы целы).

## 2. Критерии приёмки

- **AC-1.** Если истёк предел любой быстрой фазы (guard «защита репозитория», guard «публикация в
  PR», запрос предела гейта, классификация в гейте, внешний предел гейта), **статичная** команда
  (§3.1) проходит (exit 0) с предупреждением в stderr; оставшиеся проверки для неё не запускаются.
- **AC-2.** При тех же условиях любая нестатичная команда блокируется (exit 2). Статичность
  доказывается только правилом §3.1; любой сбой, таймаут или неточный вывод триажа → блок.
- **AC-3.** Сообщение блока при таймауте называет фазу, «вероятная причина — медленное окружение,
  файлы хуков не повреждены», какие команды проходят (список §3.1), диагностику для агента
  (`ls -lO .claude/hooks`) и для оператора в терминале (`time git -C <ROOT> status --short`); не
  содержит `checkout -- .claude/hooks`. На macOS при флаге `dataless` у файлов хуков сообщение и
  предупреждение прямо называют iCloud.
- **AC-4.** Быстрый режим не меняется: пока ни одна фаза не истекла, триаж не вычисляется;
  существующие тесты зелёные; шаг `pre-bash-dispatch` в `windows-commit-tier` растёт не более чем
  на 15 с.
- **AC-5.** Новые тесты красные на `v4.0.0` и зелёные после правки.
- **AC-6.** ADR §3.40 с блоком «Отклонённые варианты» (supersedes часть §3.32, обновляет named risk
  §3.38), строка в `ADR-INDEX.md`; CHANGELOG `[v4.0.1]`; версия `4.0.1` во фронтматтере
  `AGENTS.md`, `.agents/INSTALL.md`, `.agents/HOW_TO_INSTALL.md` и в
  `.agents/distribution-manifest.json`; тег `v4.0.1` в инструкции выбора выпуска `.agents/INSTALL.md`.
- **AC-7.** `.agents/HOW_TO_USE.md` — раздел troubleshooting «Bash заблокирован: проверка не
  уложилась»: признаки, проверка `ls -lO`, перенос репозитория из папки под синхронизацией iCloud.

## 3. Решение

### 3.1 Статичная команда (белый список)

Триаж решает одно: может ли команда **по построению** запустить что-либо, кроме перечисленных
программ, которые сами ничего не исполняют. Команда статична, только если выполнены все условия:

1. payload ≤ 4096 байт; в нём ровно один ключ `"command"`, его значение — строка JSON;
2. в значении нет JSON-экранирований `\\` (то есть обратной косой черты в команде), `\u`, `\b`,
   `\f`; `\n`, `\r` — разделители команд, `\t` — пробел, `\"`, `\/` — символы;
3. в команде нет `$`, обратной кавычки, `\`, `/dev/tcp`, `/dev/udp`;
4. команда делится по `;` `&` `|` `(` `)` и переводам строки (после нормализации `>&`, `<&`, `&>`
   в `>`/`<`); каждый непустой сегмент начинается со слова (до пробела, табуляции, `<`, `>`),
   **буквально** совпадающего с элементом списка, и есть хотя бы один сегмент.

Список `STATIC_COMMANDS`: `ls cat head tail wc grep stat file du df pwd cd echo date uname
whoami id hostname which type true false sleep ps uptime sw_vers cut tr uniq nl basename dirname
realpath readlink`. Каждый элемент проверен на два свойства: не исполняет внешних команд по
аргументам и не меняет состояние оболочки, от которого зависит разрешение следующей команды
(переменные, `PATH`, таблица хэшей команд, псевдонимы, функции). Сознательно исключены `printf`
(`printf -v` присваивает `BASH_CMDS[…]`, `commands[…]`, `PATH`), `find`, `xargs`, `sed`, `awk`,
`sort` (`--compress-program`), `env`, `command`, `exec`, `hash`, `time`, `nohup`, `sudo`, `less`,
`tar`, `rg`, интерпретаторы и оболочки.

Почему этого достаточно (ответ на B1/B2): слово команды сравнивается буквально, поэтому путь
(`/opt/homebrew/bin/gh`), `.exe`, кавычки, `{}`, глоб, префикс присваивания, перенаправление или
ключевое слово (`{`, `if`, `!`) на месте команды дают guarded. Подстановки и сборка слов требуют
`$`, обратной кавычки или `\` — они запрещены. Круглые скобки — разделители, поэтому тело
`<(...)`, `=(...)`, подоболочки и глоб-квалификаторов zsh проверяется как отдельная команда.
Глоб и `{}` в **аргументах** разрешённых команд безопасны: эти программы аргументы не исполняют.
Деление по разделителям внутри кавычек только добавляет сегменты (ложный guarded), но не может
скрыть настоящий.

Граница (без изменений относительно нормального режима): запись файлов перенаправлением или
инструментами Write/Edit хук Bash не охраняет ни в одном режиме.

### 3.2 Диспетчер `pre-bash.sh`

- Блок `# >>> static-triage` … `# <<< static-triage`: `STATIC_COMMANDS`, `STATIC_PAYLOAD_MAX=4096`,
  функция `static_verdict_raw` (чистый bash 3.2: без `${x,,}`, массивов, `mapfile`; внутри
  `LC_ALL=C`). Маркеры нужны тесту, чтобы прогнать весь корпус в одном процессе bash.
- `static_verdict`: один раз за вызов вычисляет `TRIAGE="$(static_verdict_raw 2>/dev/null)"` в
  подоболочке; всё, кроме точного `static`, — `guarded`. Срыв bash внутри подоболочки не завершает
  диспетчер.
- Режим `--print-static-verdict`: сразу после чтения payload печатает `static`/`guarded`, exit 0.
  `settings.json` вызывает диспетчер без аргументов.
- Ленивость: триаж вызывается только из `degrade_or_block`, то есть после кода 124. В быстром
  режиме не исполняется ни одной новой строки, кроме объявлений.
- `DEGRADED=0`. `guard()`: при `DEGRADED=1` → `return 0` без запуска; rc 124 →
  `degrade_or_block "ФАЗА"` (статична → одно предупреждение, `DEGRADED=1`; иначе `block_slow`).
- После двух guards и после запроса предела гейта: `DEGRADED=1` → `exit 0` (статичная команда не
  коммит по построению). Итог — один таймаут (~10 с) на команду.
- Запрос предела гейта: код сохраняется; 124 → `degrade_or_block`; иной ненулевой код — прежний
  блок «гейт тестов не сообщил предел прогона за … с». Внешний предел самого гейта (rc 124 из
  `guard`) обрабатывается тем же `degrade_or_block`.
- `block_slow` (exit 2), шаблон (ФАЗА, ICLOUD, СПИСОК, ROOT подставляются):
  «БЛОКИРОВКА: ФАЗА не уложилась в отведённое время; ROOT/PWD/CLAUDE_PROJECT_DIR. Вероятная
  причина — медленное окружение (диск, синхронизация, нагрузка), а не повреждение файлов:
  восстанавливать .claude/hooks не нужно. ICLOUD Пока проверки не укладываются в предел, проходят
  только простые команды из списка: СПИСОК — без $, обратных кавычек и обратной косой черты.
  Диагностика: ls -lO .claude/hooks. Для оператора в терминале: time git -C ROOT status --short».
- Предупреждение (exit 0, stderr): фаза, «команда пропущена без оставшихся проверок: простая
  команда из списка», ICLOUD. Агент его, вероятно, не видит (stderr при exit 0); канал агента —
  сообщение блока выше, оно приходит при первой же нестатичной команде.
- ICLOUD — только при `uname -s` = `Darwin`; `stat -f %Sf` по `.claude/hooks/*`,
  `.claude/tools/*.sh` и `.git/index` (метаданные, без чтения содержимого); есть `dataless` →
  «файлы выгружены iCloud (dataless): вынесите репозиторий из папки под синхронизацией iCloud
  (Documents/Desktop)».
- Подсказка `checkout -- .claude/hooks` остаётся только для отсутствующих файлов и кодов ≠ 0/2/124.
- Инварианты: строки `) exit 0 ;;`, `2) exit 2 ;;`, `QUICK_LIMIT=10`,
  `GATE_BASE="$(sh "$TIMEOUT_HELPER"`, `"$((GATE_LEFT + 20))"`,
  `export OVERGATE_COMMIT_GATE_TEST_MAX_SECONDS="$GATE_LEFT"`,
  `sh "$TIMEOUT_HELPER" "$((GATE_LEFT + 20))" bash "$HOOK_DIR/check-tests-before-commit.sh"`
  встречаются РОВНО один раз (`make_tree`); CLOSURE-004 (`scripts/check-reference.py`): на каждый
  обработчик ровно одна строка `guard "…" … "$HOOK_DIR/<handler>"`, без обёрток в условия.

### 3.3 Гейт коммита `check-tests-before-commit.sh`

Ветка `RC -eq 124` классификации спрашивает вердикт у диспетчера — правило одно, своего разбора у
гейта нет: `printf '%s' "$PAYLOAD" | "$TIMEOUT_HELPER" 5 bash "$HOOK_DIR/pre-bash.sh"
--print-static-verdict`. Точный `static` → предупреждение, exit 0; иначе прежний блок (текст
дополняется вероятной причиной). Переменных окружения между диспетчером и гейтом нет. Новая ветка
завершается только явным `exit 0` или `exit 2` (неожиданный код 1 под `set -u` хук не блокирует).
Прочие ветки гейта и прогон набора не меняются.

### 3.5 Rollback

Revert PR в `release/4.0.x` или установка `v4.0.0`: поведение возвращается к блоку на любой
таймаут. Данных и миграций нет.

### 3.6 Окружение (вне кода)

Оператор работает из клонов в `~/Developer/GitHub`; папки в `~/Documents/GitHub` — архив.

## 4. Отклонённые варианты

- **Поднять `QUICK_LIMIT`**: не лечит зависание (> 40 с), каждая команда ждёт до минуты.
- **Префильтр «без git/gh — не проверять» в нормальном режиме**: вторая истина рядом с
  классификатором, меняет семантику в быстром окружении.
- **Снять fail-closed полностью**: открывает `git push`/merge на медленной машине.
- **Чёрный список признаков (v0.2–v0.4)**: Plan Review нашёл два класса обхода (путь к бинарнику,
  `.exe`; сборка слова переносом строки, `{}`, глобом), включая коммит без тестов. Каждый новый
  синтаксис оболочки — новая дыра; доказать полноту нельзя.
- **Триаж на каждом вызове (v0.4)**: на `/bin/bash` 3.2 до 16 с на вызов и fail-open при срыве bash.
- **Переменная окружения `OVERGATE_DISPATCH_STATIC_COMMAND` (v0.4)**: лишний контракт; гейт
  спрашивает вердикт у диспетчера напрямую.
- **Триаж на Python**: интерпретатор и launcher — та самая медленная часть; bash уже исполняется.
- **Отдельный файл триажа**: меняет манифест, установщик и замкнутое множество ради одной функции.
- **Предупреждение установщика про iCloud в этом патче**: не нужно для разблокировки; отдельная
  задача Beads.

## 7. Названные риски

- **R1** В деградированном режиме нельзя ничего, кроме команд из списка: тесты, сборка и любые
  git-команды ждут восстановления окружения. Принимается: цель патча — не запирать агента и
  назвать причину; лечение окружения — §3.6.
- **R2** Ложные guarded (длинная команда, кавычки с разделителями, `\` в regex `grep`) → блок при
  таймауте, как сегодня. Принимается: fail-closed.
- **R3** На медленной ФС команды из списка тоже медленные (`cat` выгруженного файла ждёт iCloud).
- **R4** `.codex/hooks.json` (предел 5 с): таймаут хука в Codex, вероятно, не блокирует — на
  медленной машине Codex идёт без guard. Давний пробел, вне scope, отдельная задача Beads
  (заявка в `.bd-intents/`).
- **R5** Если выгружены сами `pre-bash.sh`, `with-timeout.sh` или `run-python.sh`, bash может
  зависнуть на их чтении раньше внутреннего предела; через 600 с Claude Code снимет хук без блока.
  Было и до патча; лечится только окружением.
- **R6** Предупреждение при exit 0 агент, вероятно, не видит; он узнаёт о деградации из сообщения
  блока первой же нестатичной команды.
- **R7** Bash-инструмент поднимает псевдонимы и функции из конфигурации пользователя: слово из
  списка может оказаться, например, `grep` → `rg` (`--pre`) или `cat` → `bat` (`--pager`).
  Конфигурацию задаёт пользователь, не команда; быстрый режим ведёт себя так же. Принимается.
- **R8** Быстрый режим пропускает подмену разрешения команды (`printf -v 'BASH_CMDS[ls]' …; ls …`,
  `hash -p /usr/bin/git ls; ls push …`): guards и классификатор дают ordinary. Давний пробел, вне
  scope патча, отдельная задача Beads (заявка в `.bd-intents/`).
- **R9** Если окружение отвечает ошибкой ввода-вывода, а не зависанием, guard завершится кодом 2
  (сбой импорта), а не 124, и деградированный режим не включится — как в `v4.0.0`. Не наблюдалось.

## 8. Beads

Свежий клон в `~/Developer` не имел legacy-базы; `bd init --skip-agents` подтянул устаревшую
Dolt-схему (v32) с remote, записал `sync.remote` в `.beads/config.yaml` и потребовал `migrate`.
Канон запрещает Dolt-remote, поэтому база не используется, изменённые init файлы не коммитятся,
