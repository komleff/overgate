# v4.0.1 — хук Bash не запирает агента при медленном окружении

Режим: **CRITICAL (P0)**, named risk — pipeline governance / fail-closed guard: правка решает,
какие команды проходят без полной проверки. Автор: PM (Claude Opus 5.5).

## 0. Источник, история плана и поставка

- Поручение оператора 2026-11-26: срочный Stable-патч `v4.0.1`.
- Beads: pending-заявка `.bd-intents/fix-hook-timeout-lockout.jsonl` (`tmp:hook-timeout-lockout`,
  P0). Снимок `beads-backup` `83e1feba84e1`, прочитан 2026-11-26 19:58 +07; дубликатов нет.
  Почему заявка, а не `bd create`: см. §7.
- База: ветка `release/4.0.x` создана от тега `v4.0.0` (`fc81cf4`), потому что `main` уже
  содержит Slipstream 5.0.0-rc (PR #24, #26). Рабочая ветка `fix/hook-timeout-lockout`, PR в
  `release/4.0.x`. Перенос в `main` — отдельным PR после выпуска.
- Работа идёт локально из свежего клона `~/Developer/GitHub/overgate` (вне iCloud): Bash, гейт
  коммита и тесты исполняются штатно.
- История: v0.2 — самопроверка PM (B1 путь `--print-timeout-seconds`, B2 динамические команды,

  v0.4 — перенос в репозиторий, факты поставки, Verification Contract. Независимый Plan Review
  выполняется по v0.4 (v0.2 независимого ревью не получил: субагенты стартовали из iCloud и
  зависли).

## 1. Проблема (target → as-built → gap)

**Target.** Медленное окружение замедляет агента, но не запирает его: обычные команды
(`ls`, `cat`, `grep`) проходят; охраняемые операции (git/gh мутации, коммит, публикация
готовности) по-прежнему fail-closed. Сообщение называет настоящую причину.

**As-built (`v4.0.0`).**
- `.claude/hooks/pre-bash.sh` на КАЖДЫЙ Bash-вызов последовательно запускает
  `check-repository-mutation.py`, `check-merge-ready.py` (под `QUICK_LIMIT=10` через
  `with-timeout.sh`), запрос предела `check-tests-before-commit.sh --print-timeout-seconds`
  (тоже 10 с) и сам гейт коммита. Код 124 → `block` (exit 2) с подсказкой
  `git -C <root> checkout -- .claude/hooks .claude/tools`.
- Гейт коммита классифицирует каждую команду (`commit_command_classifier.py classify-hook`) под
  `CLASSIFY_TIMEOUT_SECONDS=10`; RC 124 → exit 2.
- Факт у оператора (macOS 26.5.2, Python 3.14): с 2026-11-25 iCloud «Рабочий стол и Документы»
  выгрузил `.claude/hooks/*.py`, `check-tests-before-commit.sh`, `.git/objects/**` (`dataless`).
  `python3 -c 1` 0,02 с, но guard на payload `ls` > 40 с; `pre-bash.sh` на `ls` → 11,1 с, exit 2.
  Агент не выполняет ни одной команды и перекладывает работу на оператора.
- ADR §3.32 закрепил «быстрые guards ≤ 10 с, таймаут = блок»; §3.38 принял «флакает под
  нагрузкой» как риск. Риск «полная блокировка агента» назван не был.

**Gap.** Таймаут быстрой фазы трактуется одинаково для `ls` и для `git push`; подсказка
восстановления ложная (файлы целы).

## 2. Scope / non-goals

IN: `pre-bash.sh`, ветка RC 124 классификации в `check-tests-before-commit.sh`, тесты в
`scripts/tests/pre-bash-dispatch.test.py`, ADR §3.40 + индекс, CHANGELOG `[v4.0.1]`,
troubleshooting в `.agents/HOW_TO_USE.md`, версия/ссылки на тег.

OUT: изменение нормального (быстрого) режима проверок; классификатор и guards по существу;
Codex `.codex/hooks.json` (R4, отдельная задача); перенос в `main`; обновление установленных
проектов; переезд репозиториев оператора из iCloud (§3.6). Новых файлов поставки нет:
манифест, установщик и тесты замкнутого множества не меняются.

## 3. Решение

### 3.1 Статичная команда (триаж только при таймауте)

Команда **статична**, если её текст не содержит ничего динамического и ни одного признака
охраняемой операции. Только статичная команда может пройти без полной проверки, и только после
таймаута. Правило одно и живёт в `pre-bash.sh`; гейт коммита получает готовый вердикт.

Признаки (любой → `guarded`):
- динамика: `$`, обратная кавычка, `\u`-экранирование в JSON (fail-closed);
- подстроки после удаления `'` и приведения к нижнему регистру: `git`, `push`, `merge`, `commit`,
  `update-ref`, `refs/` (все фразы готовности гейта публикации содержат `merge`);
- слова (граница — не `[a-z0-9_./-]`): `gh sh bash zsh dash ksh fish eval source exec xargs`;
- команда `.` (точка + пробел в начале или после `;&|(`/пробела).

### 3.2 Диспетчер `pre-bash.sh` (деградированный режим)

- `STATIC_COMMAND` вычисляется один раз после `PAYLOAD="$(cat)"` функцией `static_unguarded` на
  чистом bash, без Python и без чтения файлов репозитория:
  1. Извлечь `tool_input.command` из сырого JSON: остаток после первого `"command":"` или
     `"command": "` (ключи JSON не экранируются, совпадение внутри значения невозможно — внутри
     строки `"` всегда экранирована); нет ключа → не статична. Удалить пары `\\`, затем `\"`;
     строка до первой `"`. `\n \t \r \b \f` → пробел; любая `\u` → не статична; прочие `\` удалить.
  2. Не статична при `$` или обратной кавычке.
  3. Признаки §3.1. Регулярные выражения — через переменную (`[[ $x =~ $re ]]`) ради bash 3.2.
- Режим `--print-static-verdict` (читает payload, печатает `static`/`guarded`, exit 0; до
  проверки наличия guards) — для быстрых тестов триажа. `settings.json` зовёт диспетчер без
  аргументов, поэтому поверхность записи не меняется.
- `DEGRADED=0`. `guard()`: при `DEGRADED=1` → `return 0` без запуска; rc 124 → статична:
  одно предупреждение в stderr, `DEGRADED=1`, `return 0`; не статична → `block_slow`.
- После двух быстрых guards: `DEGRADED=1` → `exit 0` (запрос предела и гейт не запускаются:
  статичная команда не коммит по построению). Итог — один таймаут (~10 с) на команду, а не 30+.
- Сбой запроса предела гейта (`--print-timeout-seconds`, путь B1): статична → предупреждение,
  `exit 0`; иначе прежний блок «гейт тестов не сообщил предел прогона за … с».
- Перед гейтом: `export OVERGATE_DISPATCH_STATIC_COMMAND="$STATIC_COMMAND"` (`0`/`1`).
- `block_slow`: «БЛОКИРОВКА: проверка «X» не уложилась в N с; ROOT/PWD/CLAUDE_PROJECT_DIR.
  Причина — медленное окружение, а не повреждение файлов: восстанавливать .claude/hooks не
  нужно.<iCloud> При медленной проверке пропускаются только статичные команды без признаков
  охраняемой операции. Проверьте окружение: time git -C <ROOT> status --short». Без
  `checkout -- .claude/hooks`; подсказка восстановления остаётся только для отсутствующих файлов
  и кода ≠ 0/2/124.
- iCloud-подсказка: только при `uname -s` = `Darwin`; `stat -f %Sf` по `.claude/hooks/*` и
  `.claude/tools/*.sh` (с ограничением времени); есть `dataless` → «файлы хуков выгружены
  iCloud (dataless) — вынесите репозиторий из папки под синхронизацией iCloud
  (Documents/Desktop)». Предупреждение деградации несёт ту же подсказку.
- Инварианты мутационных тестов: строки `) exit 0 ;;`, `2) exit 2 ;;`, `QUICK_LIMIT=10`,
  `GATE_BASE="$(sh "$TIMEOUT_HELPER"`, `"$((GATE_LEFT + 20))"`,
  `export OVERGATE_COMMIT_GATE_TEST_MAX_SECONDS="$GATE_LEFT"`,
  `sh "$TIMEOUT_HELPER" "$((GATE_LEFT + 20))" bash "$HOOK_DIR/check-tests-before-commit.sh"`
  встречаются в файле РОВНО один раз (`make_tree` требует `count == 1`).

### 3.3 Гейт коммита `check-tests-before-commit.sh`

Ветка `RC -eq 124` классификации: `OVERGATE_DISPATCH_STATIC_COMMAND` = `1` → предупреждение,
`exit 0`; иначе прежний блок. Собственного разбора команды у гейта не появляется. Прогон набора
и прочие ветки не меняются. Прямой запуск гейта без диспетчера (переменная не задана) — блок,
как в `v4.0.0`.

### 3.4 Документы

- ADR §3.40 «Деградированный режим быстрых проверок» в `.agents/PIPELINE_ADR.md`: supersedes
  часть §3.32 «таймаут быстрой проверки = блок любой команды» и обновляет named risk §3.38;
  блок «Отклонённые варианты» (§4). Строка в `docs/architecture/ADR-INDEX.md`.
- CHANGELOG `[v4.0.1]`; `HOW_TO_USE.md` — troubleshooting «Bash заблокирован: проверка не
  уложилась» (iCloud, проверка `ls -lO`, переезд в `~/Developer`); версия в README/INSTALL и
  манифесте поставки — по фактическому месту версии в `v4.0.0`.
- AC-7 (предупреждение установщика про iCloud) — только если укладывается без нового файла
  поставки и без роста commit tier; иначе задача Beads и named gap в PR.

### 3.5 Rollback

Откат — revert PR в `release/4.0.x` (или установка `v4.0.0`): поведение возвращается к
fail-closed на любой таймаут. Данных и миграций нет.

### 3.6 Окружение (вне кода)

Оператор работает из клонов в `~/Developer/GitHub`; папки в `~/Documents/GitHub` — архив.

## 4. Отклонённые варианты

- **Поднять `QUICK_LIMIT`**: не лечит зависание (> 40 с), каждая команда ждёт до минуты.
- **Префильтр «без git/gh — не проверять» в нормальном режиме**: вторая истина рядом с
  классификатором (запрещено комментарием гейта), меняет семантику в быстром окружении.
- **Снять fail-closed полностью**: открывает `git push`/merge на медленной машине.
- **Переписать проверки на bash/компилируемый язык**: объём и риск регрессий не для патча.
- **Триаж по литералам без запрета `$`/обратной кавычки (v0.2)**: `$a $b`, `eval "$X"`
  пропускались бы, хотя классификатор даёт `ambiguous` (B2).
- **Отдельный файл `hook-timeout-triage.sh` (v0.2)**: меняет манифест, установщик и замкнутое
  множество guard ради функции из 30 строк.

## 7. Названные риски и ограничения

- **R1** На таймауте динамическая команда без литералов не проходит (B2 закрыт), но
  `python3 -c` с собранной по частям строкой (`'g'+'it'`) проходит — как и в нормальном режиме
  (guard тоже не видит такой git). Рубежи: серверная защита `main`, merge только оператором, CI.
- **R2** Ложные срабатывания триажа (`digit`, `github`, `commitment`) → блок при таймауте, как
  сегодня. Принимается: fail-closed.
- **R3** На медленной ФС git-команды агента всё равно медленные; патч снимает только полную
  блокировку. Окружение — §3.6.
- **R4** `.codex/hooks.json` (предел 5 с): таймаут хука в Codex, вероятно, не блокирует —
  на медленной машине Codex идёт без guard. Давний пробел, вне scope, отдельная задача Beads.
- **R5** Каждая команда в деградированном режиме стоит ~10 с (один таймаут).
- **Beads.** Свежий клон в `~/Developer` не имел legacy-базы; `bd init --skip-agents` подтянул
  устаревшую Dolt-схему (v32) с remote, записал `sync.remote` в `.beads/config.yaml` и потребовал
  `migrate`. Канон запрещает Dolt-remote, поэтому база не используется, изменённые init файлы не
  коммитятся, задача ведётся pending-заявкой. Восстановление рабочего legacy writer — решение
  оператора.
