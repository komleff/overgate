# rc.5.1 — вернуть оператору точку входа

## Источник и решение оператора

Beads `og-bo6` (P0). Оператор 2026-11-09 (сессия PM, дословно): «В overgate и проектах, в
которых он установлен, обнаружил существенное упущение — отсутствие HOW_TO_USE.md и
сопутствующих ему PM_ROLE.md, GD_ROLE.md, SV_ROLE.md и так далее по списку из HOW_TO_USE.md
из проекта U2»; затем: «Нужно обновить overgate, чтобы у новых пользователей не возникло
подобных проблем! Срочно.» Обновление других проектов — отдельно, «по согласованию со мной»
(вне scope этого PR).

Факты PM: файлы `HOW_TO_USE.md` и шесть ролей в установленных проектах есть (managed), но с
`3766036` (PR #7, rc.1) в `HOW_TO_USE.md` нет ни одного промпта ролей; `GD_ROLE.md` в OverGate
не было никогда (PR #7 inventory: «не создавать generic GD/PD»); `.agents` скрыт в Finder.

**Решение PM по форме GD (Plan Review F1, вариант b):** generic `GD_ROLE.md` поставляется в
каждый установленный проект как файл; необязательно его **использование**, а не наличие
файла. Основание — прямое требование оператора, чтобы новые пользователи не столкнулись с
отсутствием роли из списка U2; U2 держит GD тем же способом. Удаляемый GD (вариант a)
отклонён: `preserve` воссоздаёт файл при каждом upgrade, «удаляемость» была бы мнимой.
Оператор может переиграть это решение в PR.

## Шаги

1. `HOW_TO_USE.md`: после frontmatter — H1 «Шпаргалка оператора» и разделы 1–5; прежний H1
   `# Как работать` становится `## Как работать — справочник для агентов`, его текст и все
   прежние `##`/`###` заголовки не меняются. Frontmatter version `4.0.0-rc.5.1`. Относительные
   ссылки только на файлы managed closure (не на корневой `QUICKSTART.md`).
2. `GD_ROLE.md`: generic owner — когда звать; полномочия: готовит WHAT, принимает product
   authority из `AGENTS.md` (fallback оператор), а если `AGENTS.md` назначил GD product
   authority в его области — решает в этих границах; не пишет код, не выбирает HOW, не
   обязательный verifier; маршрут через `canon-router` и project-owned пути из `AGENTS.md`;
   результат (GDD/спека с AC, ТЗ); handoff PM через `product-handoff`/`PASS_THROUGH`.
3. `AGENT_ROLES.md`: секция «Game Designer — роль проекта (не delivery owner)».
4. `check-reference.py`: `PROJECT_ROLES={'GD'}`; ROLE-001 для всех семи файлов; ROLE-002 —
   набор `.agents/*_ROLE.md` ровно шесть delivery + GD, каждый зарегистрирован в registry;
   `GUIDE-001`, `GUIDE-002` (см. таблицу).
5. Tests: `check-reference.test.py` — RED→GREEN мутации: удалён промпт любой роли → GUIDE-001;
   промпт перенесён ниже `## Beads` → GUIDE-001; переименован Beads-заголовок → GUIDE-002;
   GD не зарегистрирован → ROLE-002; лишний `XX_ROLE.md` → ROLE-002; удалён GD → ROLE-001.
   `install-distribution.test.py` — fresh (GD создан, full `check-reference` PASS);
   `RC5_SHA=9addb79…` exact install → upgrade без conflicts, byte-exact; rc.5 + проектный GD →
   upgrade → GD побайтно сохранён, full `check-reference` PASS; `--no-beads` fresh получает GD;
   rollback fresh удаляет созданный GD.
6. Manifest entry после `RV_ROLE`.
7. QUICKSTART «Что появится» + «Как ставить задачи после установки»; AGENTS template — одна
   строка-указатель (в обоих render: beads/no-beads); README — ссылка на шпаргалку.
8. ADR 3.36 (с «Отклонёнными вариантами», включая «generic GD не создавать» и «удаляемый GD»)
   + ADR-INDEX; CHANGELOG `[Unreleased] — v4.0.0-rc.5.1`, rc.5 помечен выпущенным; одна строка
   о том, что проект с изменённым `AGENT_ROLES.md` получит штатный managed conflict.

## Rollback

Revert PR. Установленные проекты: installer rollback по backup возвращает managed bytes;
созданный `preserve` GD удаляется rollback (before=None). Ручное удаление GD на payload
rc.5.1 даёт ROLE-001 FAIL — допустимо только вместе с возвратом managed payload к rc.5.
og-cfx: revert `0d9b644` и последующей правки границы возвращает полный набор в гейт коммита
(коммиты Claude снова блокируются таймаутом); установленные проекты не затронуты.
